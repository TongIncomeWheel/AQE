# PROCESS: POST MARKET (04:00–10:00 SGT; autonomous)
**Desk sequence (D-26/D-32):** the Chief adopts **Operations** for steps 2–4 (journal, portfolio check, archive — the book of record) then **Engineering & Change** for step 5 (audit + outcome — independent assurance grades the day Operations recorded). Physical move to `orchestration/` = BL-033.
**Storage note (D-84 — read this before touching any step below).** Google Drive is RETIRED as a store for the journal/PTJ/archive. GitHub is the ONE book of record: `data/journal/aegis_journal_YYYY-MM-DD.json` and `data/persistent/aegis_trade_journal_ARCHIVE_master.json` are plain files in this repo, committed and pushed by `tools/git_sync.py` every run. There is no second copy to keep in sync, no folder-ID to remember, and the janitor (`tools/janitor.py`) gets real CRUD on these files instead of a connector that can create but never delete. **This does NOT touch the AQE feed** — that is a different system boundary: AQE is an external engine we do not control, writing to its own Drive "AQE" folder as the one channel it publishes to (premarket step 3). We are not asking AQE to change how it publishes; we are only removing OUR OWN duplicate write of a file we already had in git.
**Pipeline Ledger note (D-84).** Post-market does not touch the Pipeline Ledger at all — filing and end-of-day sweep both happen in premarket now, one place, one tool, one push. There is no pipeline-ledger step in this file.

1. **Preflight (D-49).** Run `tools/preflight.py`. This session pushes at the end, so `GITHUB_PAT` must be present in `config/.env`; if MISSING, page the PM with the one-liner the tool prints. The journal still writes locally regardless — only the GitHub push needs the token.
2. **Journal snap — write, verify, push. This is Operations 1, 1a, and 2 of the `print-trade-journal` skill — see that skill for the full write taxonomy and the "write always, flag never blocks" rule.** Reconcile fills from both brokers (execution truth), roll dynCap (RB:capital.dyncap_method), build `open_positions` from the fills (Operation 1 — execution truth only; never touch `aqe_snapshot` here).
   **Then sort Aegis membership (Operation 1a) before anything else reads the file** — `tools/held_book_refresh.py classify --journal data/journal/aegis_journal_YYYY-MM-DD.json --exclusions data/persistent/non_aegis_exclusions.json --staged <today's staged-orders list>`. The PM runs other books on the same brokers, so not every fill is Aegis's: a fill matching a staged order is `confirmed` silently; a fill matching the persistent exclusion list (a ticker the PM has already rejected before) is dropped from the journal entirely, silently, and never re-flagged; anything matching neither is pulled in as `pending_review` — real capital, so it still gets stops and carry-forward — and flagged once for the PM to confirm or reject at the next premarket approval. See print-trade-journal's Aegis-membership section for the full logic; this step does not re-derive it.
   Then run Operation 2 — `tools/held_book_refresh.py carry-forward --journal data/journal/aegis_journal_YYYY-MM-DD.json --prior <the most recent prior journal that has one>` — a name with no prior snapshot anywhere is flagged `no_aqe_data` in `review_flags`, not silently left blank. Then write `data/journal/aegis_journal_YYYY-MM-DD.json` (RB:journal.naming), validate vs `contracts/journal.schema.json`. **Verify the write, don't just trust it fired:** read the file back off disk, confirm the filename matches RB:journal.naming exactly, confirm it parses as JSON and passes the schema again on the read-back copy — a write that "succeeded" but produced a mis-named or truncated file is a silent failure otherwise. Then run `tools/git_sync.py -m "post-market <DATE>"` to commit + push `data/` to GitHub — **autonomous (D-48): authenticates from `GITHUB_PAT` in config/.env, no human credential step** — and **save its JSON result to `data/eod/DATE/git_sync_result.json`** (this is what step 5's audit reads to confirm the push actually landed, not just that the command was run). **Ordering rule (Arch-F9): if the journal write, its read-back verification, or schema validation fails, STOP — no held-list emit, no archive append; page the PM.**
3. **Portfolio metrics snap — computed FOR REAL now, written INTO the journal. This is Operation 3 of `print-trade-journal` — PM: "the portfolio check figures should be inside the journal so that's a proper snapshot of the portfolio, not just list of positions."** Run `tools/portfolio_metrics.py compute --journal data/journal/aegis_journal_YYYY-MM-DD.json` — it reads the SAME file step 2 just wrote and writes the result into that file's existing `metrics` key: gross exposure, leverage, net-beta-dollar, NAV-β (gate window RB:risk.gates.portfolio_beta), sector concentration, and 1-month parametric VaR (reuses `tools/calculators/var_parametric.py`, not a second implementation). **One consistent data source, not two (PM ruling, this pass):** per-position beta and annualised volatility are computed from FMP price history via `tools/historical_store.py`, the same source and method already used for the market-factor volatility inside the VaR calc — NOT read from the AQE snapshot. AQE is only read here for `sector`, a classification, not a computed statistic. A name not yet seeded in the historical store is flagged `missing_beta_or_vol` and excluded rather than guessed. **No stop audit here** — that comparison is only ever fresh right after premarket's stop-update step; recomputing a stale tally here would just restate yesterday's numbers, so it isn't done. **Confirmed positions only:** anything still `pending_review` (see step 2's Operation 1a) is excluded from every number here and named in `excluded_pending_review`, never blended into the book until the PM actually confirms it. **Honest about AQE vintage, never fabricated:** a position with no `aqe_snapshot` at all is EXCLUDED and named in `excluded_no_aqe_data`, never defaulted to zero; `computed_from_aqe_dated` states which AQE date the sector data actually reflects (frequently NOT today's — post-market always runs before premarket refreshes it), and `mixed_vintage: true` fires if held names carry different AQE dates. **Recompute unconditionally, every run — no skip-if-no-change (PM: "it can just recalculate for all I care since no impact"):** this is a deterministic python call, no model, no network beyond the pre-seeded local store; skipping it would only ever risk a stale number for zero benefit. One file, one snapshot — no separate "metrics file."
4. **Archive-ledger append — local file, no external store (BL-046/D-68, retimed D-84).** Read the existing `data/persistent/aegis_trade_journal_ARCHIVE_master.json` (plain local read — no search-by-modifiedTime, no "which duplicate is newest" guessing, git already knows the one true version), then run `tools/archive_ledger.py merge --archive <that file> --closed <today's journal closed_trades> --today <DATE>` (deterministic, law 4 — no model math). If the tool reports `no_op: true` (no new closed trades today), **do not write.** If it reports new trades, **write the returned JSON back to the SAME local path** — an ordinary overwrite, no duplicate-file problem, `git_sync.py` in step 2 already covers `data/persistent` so it ships on the next push. **Integrity gate:** the tool raises if `sum(by_trading_day) != YTD` — on that error, do NOT write, page the PM (never ship an archive that fails its own arithmetic check).
5. **Usage & completeness audit, then emit run outcome — one mechanical pass, no narrative, no judgment (D-84, PM: "grading should be on operational loops and completeness, not market moves" / "it just needs to be mechanical saying if all jobs were done").** This grades whether the day's jobs ran, on time, without silent data problems — never whether the trades made money. Three tool calls, back to back, nothing in between them but relaying output:
   1. Read `data/eod/DATE/git_sync_result.json` from step 2 — `pushed: true` is the ground-truth confirmation the journal actually reached GitHub, not just that the kernel believed it did.
   2. Run `tools/daily_flow_audit.py DATE --render` — the flight recorder: which hierarchy layers fired today, per-layer outcomes, exceptions → `data/eod/DATE/flow_audit_DATE.{json,html}`. It folds the GitHub-push result into the Operations layer, so a failed push shows up in the flight recorder itself.
   3. Stamp the phase gate — `tools/phase_gate.py stamp --phase post_market --status ok|fail|partial --journal-date <the session date the journal covers> --note "<one line>"` — using the verdict the flow audit just computed. This is the ONLY thing tomorrow's Phase 0 reads. **Stamp honestly:** `phase_gate check` turns `status: fail` (or a journaled date whose file is missing) into **BLOCKED** = page the PM now, versus a merely-absent stamp which is **NOT_READY** = keep retrying. Stamp on EVERY exit path, including the PARTIAL/PROVISIONAL fallbacks below — a run that halts without stamping leaves Phase 0 waiting for something that is never coming.

   Then print a flat pass/fail line per job this run touched: journal written, journal verified, GitHub pushed, portfolio metrics, archive updated, audit complete, gate stamped. `run_ok` if every line is pass, `run_fail` (with the failing lines named) otherwise. Check in with the external dead-man's-switch (`tools/notify.py --checkin ok`) so the ABSENCE of a check-in becomes the alarm if the box ever dies mid-run. **CLOSE WITH A REAL CHAT MESSAGE (D-75).** `notify.py`'s print is a draft, not delivery — the Cowork push comes from the session's actual final reply. The LAST thing this session does must be that same checklist, said in plain language, as the session's actual final message — not left as a tool-call print.
   **Not yet consolidated into one script call:** these are still three separate tool invocations chained by the orchestrator, not a single wrapper — a candidate follow-up if it's worth building, not claimed as done here.

## ON FAILURE (RB:exceptions; records to data/eod/DATE/exceptions/)
- One broker pull fails → retry once → still down: reconcile from the other broker, journal marked PARTIAL_SOURCES; PAGE.
- Both pulls fail → journal from gatekeeper records only, marked **PROVISIONAL** → held-list mutations HALT; engine reuses last GOOD journal; PAGE.
- Journal fails validation, or fails its own read-back verification → HALT everything downstream (already law) + PAGE.
- GitHub push fails (`tools/git_sync.py` reports `pushed:false`) → **this is now the ONLY copy, so treat it as seriously as a journal failure**, not a soft "flag and move on." The commit is retained locally; git_sync retries next loop; PAGE with the reason. A missing `GITHUB_PAT` is reported explicitly (committed-not-pushed), never silently swallowed — fix config/.env.
- **Every exit path stamps the gate (step 5, the audit's last action before the outcome checklist).** Journal PROVISIONAL or PARTIAL_SOURCES → stamp `--status partial` with the reason; a halt at journal validation → stamp `--status fail` BEFORE paging. A run that dies without a stamp leaves Phase 0 in NOT_READY forever, retrying against a run that already failed — which reads as "AQE is late" when the truth is "post-market is dead." If the session cannot stamp at all, that silence is caught by the dead-man's-switch check-in in step 5, not by Phase 0.
