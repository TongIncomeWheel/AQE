# PROCESS: POST MARKET (04:00–10:00 SGT; autonomous)
**Desk sequence (D-26/D-32):** the Chief adopts **Operations** for steps 2–4 (journal, portfolio check, archive — the book of record) then **Engineering & Change** for steps 5–6 (ledger sweep + audit — independent assurance grades the day Operations recorded). Physical move to `orchestration/` = BL-033.
**Storage note (D-84 — read this before touching any step below).** Google Drive is RETIRED as a store for the journal/PTJ/archive. GitHub is the ONE book of record: `data/journal/aegis_journal_YYYY-MM-DD.json` and `data/persistent/aegis_trade_journal_ARCHIVE_master.json` are plain files in this repo, committed and pushed by `tools/git_sync.py` every run. There is no second copy to keep in sync, no folder-ID to remember, and the janitor (`tools/janitor.py`) gets real CRUD on these files instead of a connector that can create but never delete. **This does NOT touch the AQE feed** — that is a different system boundary: AQE is an external engine we do not control, writing to its own Drive "AQE" folder as the one channel it publishes to (premarket step 3). We are not asking AQE to change how it publishes; we are only removing OUR OWN duplicate write of a file we already had in git.

1. **Preflight (D-49).** Run `tools/preflight.py`. This session pushes at the end, so `GITHUB_PAT` must be present in `config/.env`; if MISSING, page the PM with the one-liner the tool prints. The journal still writes locally regardless — only the GitHub push needs the token.
2. **Journal snap — write, verify, push.** Reconcile fills from both brokers (execution truth), roll dynCap (RB:capital.dyncap_method), build `open_positions` from the fills (execution truth only — qty, entry, stop_reference, etc; never touch `aqe_snapshot` here). **Carry the held-book loop forward (D-85) before anything else reads this file:** run `tools/held_book_refresh.py carry-forward --journal data/journal/aegis_journal_YYYY-MM-DD.json --prior <the most recent prior journal that has one>` — post-market runs BEFORE premarket pulls AQE each day, so this is the only way today's positions start with ANY market-data context; each snapshot keeps its true `aqe_snapshot_as_of` (usually a day or more old — never re-stamped to look fresher). A name with no prior snapshot anywhere stays null and portfolio_metrics.py (step 3) excludes it rather than guessing. Then write `data/journal/aegis_journal_YYYY-MM-DD.json` (RB:journal.naming), validate vs `contracts/journal.schema.json`. **Verify the write, don't just trust it fired:** read the file back off disk, confirm the filename matches RB:journal.naming exactly, confirm it parses as JSON and passes the schema again on the read-back copy — a write that "succeeded" but produced a mis-named or truncated file is a silent failure otherwise. Then run `tools/git_sync.py -m "post-market <DATE>"` to commit + push `data/` to GitHub — **autonomous (D-48): authenticates from `GITHUB_PAT` in config/.env, no human credential step** — and **save its JSON result to `data/eod/DATE/git_sync_result.json`** (this is what step 6's audit reads to confirm the push actually landed, not just that the command was run). **Ordering rule (Arch-F9): if the journal write, its read-back verification, or schema validation fails, STOP — no ledger/pipeline mutation, no held-list emit, no archive append; page the PM.**
3. **Portfolio metrics snap — computed FOR REAL now, written INTO the journal (D-85, PM: "the portfolio check figures should be inside the journal so that's a proper snapshot of the portfolio, not just list of positions").** Run `tools/portfolio_metrics.py compute --journal data/journal/aegis_journal_YYYY-MM-DD.json` — it reads the SAME file step 2 just wrote (with whatever `aqe_snapshot` step 2's carry-forward attached to each held name) and writes the result into that file's existing `metrics` key: gross exposure, leverage, net-beta-dollar, NAV-β (gate window RB:risk.gates.portfolio_beta), sector concentration, stop audit (live vs reference, MATCH/MISMATCH/MISSING — already per-position in the schema), and 1-month parametric VaR (reuses `tools/calculators/var_parametric.py`, not a second implementation). **Honest about vintage, never fabricated:** a position with no `aqe_snapshot` at all is EXCLUDED from leverage/beta/sector/VaR and named in `excluded_no_aqe_data`, never defaulted to zero; `computed_from_aqe_dated` states which AQE date the numbers actually reflect (frequently NOT today's — post-market always runs before premarket refreshes it, see step 2), and `mixed_vintage: true` fires if held names carry different AQE dates. One file, one snapshot — no separate "metrics file." Moved directly after the journal (D-84/D-85 ruling) — this is the second half of "is the book of record correct," and it should happen before any lower-priority housekeeping (archive, sweep), not after.
4. **Archive-ledger append — local file, no external store (BL-046/D-68, retimed D-84).** Read the existing `data/persistent/aegis_trade_journal_ARCHIVE_master.json` (plain local read — no search-by-modifiedTime, no "which duplicate is newest" guessing, git already knows the one true version), then run `tools/archive_ledger.py merge --archive <that file> --closed <today's journal closed_trades> --today <DATE>` (deterministic, law 4 — no model math). If the tool reports `no_op: true` (no new closed trades today), **do not write.** If it reports new trades, **write the returned JSON back to the SAME local path** — an ordinary overwrite, no duplicate-file problem, `git_sync.py` in step 2 already covers `data/persistent` so it ships on the next push. **Integrity gate:** the tool raises if `sum(by_trading_day) != YTD` — on that error, do NOT write, page the PM (never ship an archive that fails its own arithmetic check).
5. **Pipeline Ledger — sweep only (D-83/D-84). Filing moved to premarket, immediately after the committee decides (D-84, PM: "we file immediately after premarket... it eventually feeds into intraday monitoring").** This step does NOT file new proposals — that already happened same-day, right after premarket's committee deliberation, so `trigger_silent` names are visible to the market-hours sweep the same afternoon instead of waiting for tonight's post-market run. Post-market's job here is purely the END-OF-DAY evaluation: run `tools/pipeline_ledger.py sweep --date DATE --export output/aqe_daily_export.json` — expires rows past their TTL and marks any `trigger_silent` row whose condition fired on today's close. A missing field never counts as a satisfied trigger; unevaluable rows are listed, not assumed. Anything that fired, plus the active count, goes in the 10:00 summary. **Gated by step 2's ordering rule (Arch-F9): if the journal write or validation failed, this step does not run at all.**
6. **Usage & completeness audit — this is the ONLY grading post-market does, and it grades COMPLETION, not market performance (D-84, PM ruling: "there is no basis set, and even if there was, grading should be on operational loops and completeness, not market moves").** Per voice and committee: ran? on time? data pulls tagged? any fabrication/staleness? → `data/audit/audit_YYYY-MM-DD.json` (RB:audit). **GitHub-landed verification (D-84, supersedes D-69's Drive check):** read `data/eod/DATE/git_sync_result.json` from step 2 — `pushed: true` is the ground-truth confirmation the book of record actually reached GitHub, not just that the kernel believed it did (a `git push` returning success has no fire-and-forget failure mode, so this is a STRONGER guarantee than the old Drive listing-check ever gave). Then the **DAILY AGENTIC-FLOW AUDIT (D-43): `tools/daily_flow_audit.py DATE --render`** reconstructs, from the day's shelf, which hierarchy layers actually fired (Chief → Research/10-voice swarm → Committee-desk → Risk/dynCap·VaR·gates → Execution/gatekeeper → Engineering·self-heal → Operations), with per-layer outcomes, inferred spawn count, and exceptions → `data/eod/DATE/flow_audit_DATE.{json,html}` — it folds the GitHub-push result into the Operations layer, so a failed push shows up in the flight recorder itself. This is the flight recorder — coverage of the flow (a grey "not run" layer is itself the signal). **Stamp the phase gate as the LAST action of this step (D-83/D-84 — folded in, not a separate step):** run `tools/phase_gate.py stamp --phase post_market --status ok|fail|partial --journal-date <the session date the journal covers> --note "<one line>"`, using the verdict THIS audit just computed. This is post-market's hand-off and the ONLY thing tomorrow's Phase 0 reads. **Stamp honestly — a `fail` stamp is a useful stamp:** `phase_gate check` turns `status: fail` (or a journaled date whose file is missing) into **BLOCKED** = page the PM now, versus a merely-absent stamp which is **NOT_READY** = keep retrying. Stamp on EVERY exit path, including the PARTIAL/PROVISIONAL fallbacks below — a run that halts without stamping leaves Phase 0 waiting for something that is never coming.
7. **Emit run outcome — mechanical checklist, not a narrative (D-84, PM: "it just needs to be mechanical saying if all jobs were done").** Print a flat pass/fail line per job this run touched: journal written, journal verified, GitHub pushed, portfolio metrics, archive updated, ledger swept, audit complete, gate stamped. `run_ok` if every line is pass, `run_fail` (with the failing lines named) otherwise. Then check in with the external dead-man's-switch (`tools/notify.py --checkin ok`) so the ABSENCE of a check-in becomes the alarm if the box ever dies mid-run. **CLOSE WITH A REAL CHAT MESSAGE (D-75).** `notify.py`'s print is a draft, not delivery — the Cowork push comes from the session's actual final reply. The LAST thing this session does must be that same checklist, said in plain language, as the session's actual final message — not left as a tool-call print.

## ON FAILURE (RB:exceptions; records to data/eod/DATE/exceptions/)
- One broker pull fails → retry once → still down: reconcile from the other broker, journal marked PARTIAL_SOURCES; PAGE.
- Both pulls fail → journal from gatekeeper records only, marked **PROVISIONAL** → ledger/held-list mutations HALT; engine reuses last GOOD journal; PAGE.
- Journal fails validation, or fails its own read-back verification → HALT everything downstream (already law) + PAGE.
- GitHub push fails (`tools/git_sync.py` reports `pushed:false`) → **this is now the ONLY copy, so treat it as seriously as a journal failure**, not a soft "flag and move on." The commit is retained locally; git_sync retries next loop; PAGE with the reason. A missing `GITHUB_PAT` is reported explicitly (committed-not-pushed), never silently swallowed — fix config/.env.
- Pipeline Ledger sweep fails → accounting is already done and safe; log it, note it in the morning summary, defer to tomorrow. **Never block the journal or the phase-gate stamp on the ledger** — the ledger is a convenience store for ideas, not the book of record.
- **Every exit path stamps the gate (step 6, the audit step's last action).** Journal PROVISIONAL or PARTIAL_SOURCES → stamp `--status partial` with the reason; a halt at journal validation → stamp `--status fail` BEFORE paging. A run that dies without a stamp leaves Phase 0 in NOT_READY forever, retrying against a run that already failed — which reads as "AQE is late" when the truth is "post-market is dead." If the session cannot stamp at all, that silence is caught by the dead-man's-switch check-in in step 7, not by Phase 0.
