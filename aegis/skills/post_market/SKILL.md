# PROCESS: POST MARKET (04:00–10:00 SGT; autonomous)
**Desk sequence (D-26/D-32):** the Chief adopts **Operations** for steps 1–2 (journal, metrics — the book of record) then **Engineering & Change** for steps 2b–3 (scorer + audit — independent assurance grades the day Operations recorded). Physical move to `orchestration/` = BL-033.
0. **Preflight (D-49).** Run `tools/preflight.py`. This session pushes at the end, so `GITHUB_PAT` must be present in `config/.env`; if MISSING, page the PM with the one-liner the tool prints. The journal/book still write locally + to Drive regardless — only the git push needs the token.
1. **Journal snap.** Reconcile fills from both brokers (execution truth), roll dynCap (RB:capital.dyncap_method), write `data/journal/aegis_journal_YYYY-MM-DD.json` (RB:journal.naming), validate vs contracts/journal.schema.json. **PTJ emission — kernel-native (D-67, print-trade-journal successor).** The book of record is ALSO written to Drive under the PM's locked naming convention — `aegis_trade_journal_[YYYY-MM-DD]_PTJ.json` — into the canonical PTJ folder (id `15PR74ws_kTXTqCcEfRGga_jjHrMvbCEM`) via `mcp__Google_Drive__create_file` (`disableConversionToGoogleType: true`, `contentMimeType: application/json`), content = the same validated journal record. This is the ONE PTJ writer — it replaces the standalone `print-trade-journal` skill dependency (BL-046/D-67: that skill lives outside the kernel and can be silently toggled off by a plugin reinstall, which is exactly what produced the 07-18→07-20 stale-PTJ gap this decision closes). No external skill call, no toggle to forget. Then run `tools/git_sync.py -m "post-market <DATE>"` to commit + push the day's shelf/state to GitHub — **autonomous (D-48): it authenticates from `GITHUB_PAT` in config/.env and pushes with no human credential step.** **Ordering rule (Arch-F9): if the journal write or validation fails, STOP — no ledger/pipeline mutation, no held-list emit, no PTJ emission; page the PM.**
1b. **Archive-ledger append — kernel-native (BL-046/D-68, print-trade-journal successor part 2).** After PTJ emission, close the second half of the retired skill: search the PTJ folder for `aegis_trade_journal_ARCHIVE_master.json` (if duplicates exist, read the one with the latest `modifiedTime` — the connector has no delete/overwrite, see the housekeeping note below), read it, then run `tools/archive_ledger.py merge --archive <fetched> --closed <today's journal closed_trades> --today <DATE>` (deterministic, law 4 — no model math). If the tool reports `no_op: true` (no new closed trades today), **do not write** — this preserves the retired skill's step 2i rule and avoids a no-op duplicate file. If it reports new trades, write the returned JSON back to Drive via `mcp__Google_Drive__create_file` with the SAME title `aegis_trade_journal_ARCHIVE_master.json` in the same PTJ folder (the connector cannot delete the prior copy — see below). **Integrity gate:** the tool raises if `sum(by_trading_day) != YTD` — on that error, do NOT write, page the PM (never ship an archive that fails its own arithmetic check). **Housekeeping check (from the retired skill, preserved):** count files matching `aegis_trade_journal_*_PTJ.json` in the PTJ folder; if > 10, note it in the run outcome ("N PTJ snapshots — PM may wish to tidy") — **no auto-move/delete** (the connector has no delete/move tool; this was true of the old skill too, "user handles cleanup when prompted," and remains a manual PM action in the Drive UI).
2. **Portfolio metrics snap.** Exposure, leverage, NAV-β (gate window RB:risk.gates.portfolio_beta), VaR, sector concentration, stop audit (live vs reference, MATCH/MISMATCH/MISSING) → metrics file + flags.
2b. **Criteria evaluation + voice memory (D-14).** The scorer evaluates the day against RB:performance (per-voice hit/excess targets, committee precision, plan trigger quality, execution slippage, system uptime) → `scorecard.json` (contracts/scorecard.schema.json) with PASS / WATCH / FAIL verdicts; two consecutive failing windows on any voice = automatic Engineering Bench review item. Then `tools/voice_memory.py update --scorecard <scorecard>` rebuilds every voice's bounded memory (stats vs targets, open picks, last-10 outcomes, standing lessons with evidence + expiry) — what each voice reads at tomorrow's spawn.
2c. **Trailing-stop recompute (D-33, Risk desk).** For every held Aegis position, the exits skill runs `tools/calculators/trailing_stop.py` (RB:trailing) to compute tomorrow's stop — breakeven→structure ratchet, milestone locks, NEVER lowering. Any raised stop becomes a TIGHTEN_STOP request to the staging-gatekeeper for next session; a returned EXIT signal (structure reached price) is flagged for the plan. This is the nightly half of the trail cadence (the intraday half fires on target-hit alerts in market hours).
2d. **Pipeline Ledger — file what the committee proposed (D-83). Filing only; no judgement here.** Read today's `data/sod/DATE/committee.json` and run `tools/pipeline_ledger.py persist --committee <that file> --date DATE`. The tool takes ONLY the verdicts carrying a `ledger_proposal` the committee itself attached — a name the committee did not propose is dropped, and that is the correct outcome. **Post-market does NOT classify, re-rank, or sweep in everything that failed to advance**; the judgement was made once, live, at deliberation time, and this step is a mechanical write (law 4, no model). The tool rejects two things loudly and they ride in the run outcome: a `trigger_silent` proposal with no stated trigger (it would be parked forever), and a proposal on an ADVANCE name (it is in the plan, not the pipeline). A re-proposed name extends its TTL instead of creating a second row. **A name the committee ADVANCED today has its pipeline row CLOSED automatically** (`closed_advanced` in the tool's output) — it is now a plan line, and leaving it active would double-track the same idea in two places until its TTL quietly expired. Then run `tools/pipeline_ledger.py sweep --date DATE --export output/aqe_daily_export.json` — expires rows past their TTL and marks any `trigger_silent` row whose condition fired on today's close. A missing field never counts as a satisfied trigger; unevaluable rows are listed, not assumed. Anything that fired, plus the active count, goes in the 10:00 summary — this is the PM's glance, per the interview ("post-market sorts it, I confirm at premarket"). **Gated by step 1's ordering rule (Arch-F9): if the journal write or validation failed, this step does not run at all.**
3. **Usage & completeness audit.** Per voice and committee: ran? on time? data pulls tagged? any fabrication/staleness? → `data/audit/audit_YYYY-MM-DD.json` (RB:audit). **Independent Drive-PTJ verification (D-69 — audit the world, not the kernel's belief about the world).** Every prior audit tool here reads ONLY local repo/workspace files — it can confirm the kernel's own write step ran, but never that the write actually landed in Drive (this exact blind spot is why the 07-18→07-20 stale-PTJ gap went undetected by Design & Review — the PTJ job lived entirely outside the kernel's field of view). So after step 1b: call `mcp__Google_Drive__search_files` for `parentId = '15PR74ws_kTXTqCcEfRGga_jjHrMvbCEM' and title contains 'PTJ'`, save the raw result to `data/eod/DATE/ptj_drive_listing.json`, then run `tools/drive_ptj_check.py check --listing <that file> --date DATE --out data/eod/DATE/ptj_drive_check.json` (deterministic, law 4). A non-`FRESH` verdict (STALE/MISSING) means the write step believed it succeeded but Drive shows otherwise — treat as a write failure: page the PM, do not report the day as fully green. A `housekeeping_flag: true` (>10 PTJ files) rides in the run outcome as a tidy-up note, same as step 1b's own housekeeping check. **Then the DAILY AGENTIC-FLOW AUDIT (D-43): `tools/daily_flow_audit.py DATE --render` reconstructs, from the day's shelf, which hierarchy layers actually fired (Chief → Research/10-voice swarm → Committee-desk → Risk/dynCap·VaR·gates → Execution/gatekeeper → Engineering·self-heal → Operations), with per-layer outcomes, inferred spawn count, and exceptions → `data/eod/DATE/flow_audit_DATE.{json,html}` — it now folds `ptj_drive_check.json` into the Operations layer (D-69), so a Drive-write failure shows up in the flight recorder itself, not just in this step's page. This is the flight recorder — coverage of the flow (a grey "not run" layer is itself the signal), distinct from the integrity audit above (fabrication/sources). The HTML card rides the 10:00 morning summary to the PM's phone.**
4. Outputs feed straight into Design & Review; PM sees everything in the 10:00 morning summary.
4b. **Stamp the phase gate — the LAST write of the run (D-83).** Run `tools/phase_gate.py stamp --phase post_market --status ok|fail|partial --journal-date <the session date the journal covers> --note "<one line>"`. **This is post-market's hand-off, and it is the ONLY thing tomorrow's Phase 0 has to read.** Premarket's expensive half depends on this journal being current; until now that dependency was a clock guess (premarket happens to be scheduled a few hours later) with the freshness check buried inside the same session that would go on to spend the full build anyway. The stamp turns it into a real gate that costs two file reads. **Stamp honestly — a `fail` stamp is a useful stamp**: `phase_gate check` turns `status: fail` (and a journaled date whose file is missing) into **BLOCKED** = page the PM now, versus a merely-absent stamp which is **NOT_READY** = keep retrying. Getting this wrong in the optimistic direction means tomorrow's plan gets built on stale truth, which is the failure this whole gate exists to prevent. Stamp on EVERY exit path, including the PARTIAL/PROVISIONAL fallbacks in the ladder below — a run that halts without stamping leaves Phase 0 waiting for something that is never coming.
5. **Emit run outcome + watchdog check-in (D-45).** Emit `tools/notify.py run_ok` with the day's headline (or `run_fail` if journal/accounting halted). PAGE in the ladder below = `tools/notify.py run_fail`; a transient broker-pull failure first attempts `tools/self_heal.py post-market --failure ptj_pull` (bounded retry, RB:self_heal) before the PARTIAL/PROVISIONAL fallbacks. Then check in with the external dead-man's-switch (`tools/notify.py --checkin ok`) so the ABSENCE of a check-in becomes the alarm if the box ever dies mid-run. **CLOSE WITH A REAL CHAT MESSAGE (D-75).** `notify.py`'s print is a draft, not delivery — the Cowork push comes from the session's actual final reply. The LAST thing this session does must be a plain-language message carrying the same run_ok/run_fail body, same requirement as premarket step 12.

## ON FAILURE (RB:exceptions; records to data/eod/DATE/exceptions/)
- One broker pull fails → retry once → still down: reconcile from the other broker, journal marked PARTIAL_SOURCES; PAGE.
- Both pulls fail → journal from gatekeeper records only, marked **PROVISIONAL** → ledger/held-list mutations HALT; engine reuses last GOOD journal; PAGE.
- Journal fails validation → HALT everything downstream (already law) + PAGE.
- GitHub push fails (`tools/git_sync.py` reports pushed:false) → the commit is retained locally and the book/state is still safe in Drive (autonomous connector); git_sync retries next loop; flag it in the morning summary. A missing `GITHUB_PAT` is reported explicitly (committed-not-pushed), never silently swallowed — fix config/.env.
- Scorer/learning failures never block accounting — they defer to tomorrow and are noted.
- Pipeline Ledger persist/sweep fails → accounting is already done and safe; log it, note it in the morning summary, defer to tomorrow. **Never block the journal or the phase-gate stamp on the ledger** — the ledger is a convenience store for ideas, not the book of record.
- **Every exit path stamps the gate (step 4b).** Journal PROVISIONAL or PARTIAL_SOURCES → stamp `--status partial` with the reason; a halt at journal validation → stamp `--status fail` BEFORE paging. A run that dies without a stamp leaves Phase 0 in NOT_READY forever, retrying against a run that already failed — which reads as "AQE is late" when the truth is "post-market is dead." If the session cannot stamp at all, that silence is caught by the dead-man's-switch check-in in step 5, not by Phase 0.
