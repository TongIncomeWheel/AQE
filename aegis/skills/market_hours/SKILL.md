# PROCESS: MARKET HOURS (21:30–04:00 SGT; autonomous — RB:schedule)
**Desk sequence (D-26/D-32):** the Chief adopts **Execution** throughout (watch, staging), briefly re-borrowing **Research**'s voices for the intraday review pod (step 3c). Physical move to `orchestration/` = BL-033. Principle: **code watches, agents wake** (RB:schedule.market_watch_mode).
**Model note (D-16):** this orchestrator (and the AQE watcher it wraps) is control plane — RB:model_tiers.control. Assembling the live pack and tallying the pod's verdict is sequencing, not judgment. The pod's voices (step 3c) are the same pinned RB:model_tiers.judgment agent files as the premarket swarm — spawning them on the live pack costs nothing extra to wire, the tier travels with the agent file, not with who calls it.

1. **Alerts arrive via a FILE, never email (D-62 capture pattern; D-82 cadence + source).** The AQE engine writes its alerts every **30 min** (D-82 — changed from 15; the email feed is retired) to the Drive "AQE" folder → `aegis/data/alerts/DATE/inbox.jsonl` (JSONL per `contracts/alert_inbox.schema.json`), scoped to **today's AQE alert list** (`data/alerts/DATE/alert_list.json` — the A∪B∪C∪P amalgam built at premarket step 10, D-82/D-83: **List A** casting-mat top-50 data+detect + **List B** strongest-5-day-Elder top-15 + **List C** up-to-10-per-voice committee nominations + **List P** the Pipeline Ledger's active `trigger_silent` rows — names a previous committee PARKED on a stated condition, D-83). Each alert is a **BRACKET-LEVEL event** (D-82) — `entry_cross`, `breakout_2pct_cob` (+2% over prior COB), `sl_approach`, `sl_hit` — carrying its **category (A/B/C) + why**, NOT the full PTRS (the category tells you which longlist logic surfaced it and why there's an alert). The scheduled market-watch session SWEEPS with `tools/alert_inbox.py` (deterministic, no models): dedupe vs cursor → confirm the name is on today's `alert_list.json` → enrich from the export. Routing: **held-book stop/approach → page immediately** (the risk stream, D-58); an **on-alert-list opportunity event** (`entry_cross` / `breakout_2pct_cob` on a List A/B/C name) → **pod-worthy → request committee deliberation** (the market-hours agent's one job, D-82); a **List P (parked) name** routes the same way with one addition — the entry carries the row's own `pipeline.trigger` (`{field, op, value}`), so the sweep checks that stated condition against the enriched record as well as the bracket, and the wake reason is the condition the committee named, not a generic breakout. **A parked name that fires is podded WITH its `case_snapshot`** so the pod re-reads the case that parked it instead of meeting the name cold. A missing field is never a satisfied trigger — it is logged unevaluable, same rule as the post-market sweep. Everything else — off-list, event-driven, stale — is **logged, not podded** (kept visible, D-61). Code watches; agents wake only on a survivor. (Supersedes the 15-min email framing: the poll is the AQE engine's 30-min file on the alert-list membership, the sweep + deliberation request is the session's.)
1a. **CHEAP BY DEFAULT + HELD-BOOK FIRST (D-58, PM + Thorp).** The routine 30-min poll runs on the **watch tier = haiku** [RB:model_tiers.watch] — never opus on a routine cycle (anti-cost, anti-overfit). Its PRIMARY, always-on job is the **held-book risk stream** (the durable positive-EV work): for every open position, on every cycle, check SL hit / SL approaching (~0.5 ATR), TP1/TP2/TP3 hit → scale-out + trail, and trailing-ratchet availability (a new higher swing-low). These are deterministic reads on the bracket + live price; haiku assembles and pages, no judgment tier needed. Held-book protection is checked BEFORE any opportunity scan.
1b. **Two wake paths for OPPORTUNITY (D-54), and when to spend a bigger model:**
   - **On-plan name** (approved actionable) crosses its live level → full re-validation (step 3) + Intraday Review Pod (step 3c).
   - **Off-plan runner** (a breakout the morning didn't pick, on the strong-momentum universe) → the `alert_inbox.py` runner-gate (step 1) already triaged, so the pod runs only on the **survivors**. The pod **evaluates the alert name EXACTLY as the voices evaluate a premarket candidate** (D-63, corrected) — their own methodology and normal conviction (1–5), the SAME logic as the SOD swarm. It is NOT a special "runner" mode and NOT a perfectionist stand-down; there is **one evaluation, used at SOD and intraday** (anti-spaghetti). **These voices were chosen because they are momentum traders** (O'Neil, Minervini, Livermore/Darvas lineage, Druckenmiller, Wyckoff, elder/detect), so their native lens already speaks to a momentum book — the system's ONLY duty is to not distort them: **no extension / R:R / perfection filter layered ON TOP** (that turns momentum trading into swing/position trading), and **no positive-bias cheerleading layered UNDER**. Extension above the MA is momentum STRENGTH, not a flaw (PBF, 18 Jul: mp 100, rs +66, structure 87 — 41% extended — a leader the perfectionist filter would have wrongly killed). Run the relevant voices on the live pack as a premarket-style nomination; the Chief then runs the **BRACKET EXERCISE** (stop, resistance-vs-entry, R:R — the risk, D-52) and pages the PM on genuine voice conviction with the bracket; the PM decides the R:R. **The pod runs only on survivors** (few), so a 15-min cadence stays cheap.
   - **ARMED auto-deliberate-and-execute (D-58, opt-in):** if `RB:autopilot.auto_deliberate_execute` is armed, an escalated mover that reaches **consensus ≥ RB:autopilot.auto_execute_consensus_min (6 voices)** auto-executes within caps via the staging-gatekeeper (still the sole order path); **below 6 it pages, never auto-fires.** Off-plan names still auto-execute only under this armed switch and only through the gatekeeper. Default OFF → preview/page only.
2. On an ON-PLAN trigger fire: orchestrator wakes with the alert + the approved plan entry for that name only.
3. Re-validation (short, bounded): plan conditions still true (spot vs trigger, event check, gap sanity)? Uses live spot per RB:data_sources.
3b. **Live data pack (D-13).** Assemble before any order request: live spot · distance to stop/targets from the name's feed bracket · the name's full feed record · **live sector pulse** (`tools/srm_live.py` — 11 sector ETFs + macro proxies, TAILWIND/NEUTRAL/HEADWIND + RISK_ON/OFF tone) · macro proxies. Pulse unavailable = NEUTRAL-UNKNOWN, said out loud.
3c. **Intraday Review Pod (D-13).** The alert re-convenes a BOUNDED committee: the voices that nominated this name + Druckenmiller (macro) + the Detect lens — each spawned isolated with the live pack, returning one line: **CONFIRM** or **STAND_DOWN** + reason. Majority CONFIRM required to proceed. The pod may NOT add names, may NOT change brackets or sizes, may NOT resurrect a stood-down name — confirm or stand down, nothing else. A sector HEADWIND or RISK_OFF tone is exactly the kind of reason a pod stands down. Verdict + reasons written to intraday/DATE/pod/.
4. Action by phase (RB:orders / RB:autopilot): Phase 1 — if the PM pre-staged the bracket, log the fire and monitor; if not staged, record MISSED-BY-DESIGN with price path. Any order-shaped need routes as a REQUEST to staging-gatekeeper — this orchestrator can never stage (feeds Design & Review; this is the evidence that will justify Phase 2). Phase 2 (when enabled) — auto-stage within caps, notify.
4b. **Target-hit → exits (D-33, intraday half of the trail cadence).** On a take-profit alert (price reaches TP1/TP2/TP3), the Chief adopts **Risk**'s exits skill: issue the scale-out (RB:trailing.scale_out — fraction at TP1/TP2, run the rest) AND tighten the trailing stop at once (milestone lock ≥entry after TP1, ≥TP1 after TP2). Both route as requests to the staging-gatekeeper — this orchestrator never places. Protects the spike without waiting for post-market.
5. Fills observed via broker pull → held-book memory updated (entry, stop, date, trigger, TPs) — this is Execution-class work, same field list and same journal file as the `print-trade-journal` skill's Operation 1, just triggered live instead of at post-market's end-of-day reconciliation. **Push it, same reason premarket does:** run `tools/git_sync.py -m "market-hours fill <ticker> <DATE>"` right after the update — this scheduled run is its own session with its own checkout, and a fill that only lands on this session's local disk is invisible to tomorrow's post-market carry-forward and to the next market-hours firing. Skip the push on a cycle where nothing fired (most cycles) — this is a per-fill action, not a per-poll one. Post-fill protocol runs in staging-gatekeeper (its owner), not here.
6. Every wake, one line to the overnight log — nothing else. No commentary, no re-deliberation of the plan.

## ON FAILURE (RB:exceptions; records to data/intraday/DATE/exceptions/)
- 21:25 liveness check: alert engine not alive → PAGE IMMEDIATELY (your call: fix, stay up, or accept broker stops for the night). BL-018.
- Live spot unavailable at re-validation → that trigger STANDS DOWN, logged MISSED_BY_FAILURE; never confirm on stale spot.
- Broker unreachable while ARMED → DISARM FIRST, then page. Preview mode: log and wait for the next fire.
- Gatekeeper cannot READ any check file → that is a refusal (fail-closed), not an override opportunity.
- Any anomaly at all while armed → DISARM FIRST, ask questions at 10am.
