# PROCESS: PREMARKET (weekdays; plan ready 16:00 SGT, PM approval by 21:00 — RB:schedule)
**Desk sequence (D-26/D-32):** the Chief adopts **Research** (steps 1–9: universe, swarm, tally, event filter, weather, deliberation) → **Risk** (step 10 sizing + gates) → **PM approval** (step 11) → **Execution** (step 11 staging requests). Physical move to `orchestration/` = BL-033. Voices work in isolation at step 5. No numbers here — all thresholds are RB: keys.
**Model note (D-16):** you, the orchestrator running this skill, are control plane — RB:model_tiers.control. Your job is sequencing, tool calls, and contract validation, never analysis. Every step that needs real judgment (the swarm at step 5, deliberation at step 9) is delegated to a pinned judgment-tier agent — RB:model_tiers.judgment, baked into that agent's own compiled file. Don't reason hard here; spawn, validate, move on.

0. **Preflight (D-49).** Run `tools/preflight.py`. If `GITHUB_PAT` is MISSING, the post-market push will fail — page the PM to paste it into `config/.env` (the tool prints the exact one-liner) and continue the read/compute work regardless (the token is only needed at the post-market commit, not to run premarket). Never block the plan on it; never fabricate a token.
1. **Freshness check.** Journal current? AQE export dated today (RB:data_sources.staleness)? If stale → fix/notify first, do not proceed silently.
2. **Universe build.** Run `tools/universe_screen.py` (RB:universe.screen) → `data/sod/DATE/universe.json` (the only file voices nominate from) PLUS a `near_misses` list (D-37, RB:universe.near_miss) — names just outside the screen (within band on EMA/vol). Near-misses are NOT nominated, but they are SURFACED in the plan so the committee/PM can revive one — the screen is no longer a silent early cut.
3. **AQE pull — from the Drive "AQE" folder (D-66, PM-confirmed the canonical source).** The AQE engine writes `aqe_daily_export.json` to the Google Drive folder named **"AQE"** (id `1CJMoI19Zf_ZFeU5_5uhW9l92IB8fVger`) on its daily run — that folder IS the feed, and a fresh scheduled session already has the Google Drive connector, so the kernel PULLS it directly (no PC-side git push, no assumption it is pre-staged on disk). Procedure: search the "AQE" folder for `aqe_daily_export.json`, download it to `output/aqe_daily_export.json`, and **check freshness — the export's internal `date` must be today (T-1 at the oldest, PM-acknowledged per RB:data_sources.staleness); a stale or missing export STANDS THE PHASE DOWN with a page, it does NOT proceed on nothing** (the 18–20 Jul empty-Ledger root cause — the export never reached the workspace). Then validate against `contracts/aqe_export.schema.json`; run `tools/tripwires.py` (blocks on anomaly). Extract the working read only — full subcomponents stay on disk until a name reaches deliberation. (The intraday `aqe_ma_scan.json` / alert inbox is a separate, lesser feed for the market-hours `/loop`; keep it in the same "AQE" folder so there is ONE feed location.)
4. **Held book FIRST — exits before entries (D-33).** The Aegis held book is read from the latest **Aegis PTJ file** — the one source already filtered to the AEGIS sub-fund (D-17/D-21), NOT the raw broker account nor the AQE export's `held_positions` (which mismatched the live account 18 Jul — BL-024). Before any new idea is sized, the Chief adopts **Risk** and runs the **exits skill** (`desks/risk/exits`, `trailing_stop.py`) for the MATH: recompute each trailing stop (mechanical FLOOR — breakeven→structure ratchet, never lowers), compute per-sector exposure (RB:risk.gates.sector_exposure), and identify rotation candidates. The held JUDGMENT — RUN / TAKE-PARTIAL / TIGHTEN / EXIT per name, from price-vs-ATR-range + structural levels + runner-vs-weakening — is the **committee's**, produced at step 9 (D-34); step 10 combines the committee read with the mechanical floor so the **PM decides partial-vs-run**. **dynCap refresh (D-41 — mark-to-market): because the PTJ is already loaded here with open positions marked to price, the orchestrator runs `tools/dyncap_ledger.py update <ptj>` NOW — dynCap = allocation + realised + unrealised = current Aegis equity, so every size today is against what is actually held (it de-sizes in drawdown). This is the daily refresh; a stale mark is never used.** Freed/protected capital and the refreshed dynCap set what is available for new sizing. Within this step the **hedge assessment** runs (BL-007, wired 18 Jul): Phase 1 — coverage matrix from the AQE `held_book` (beta-adjusted exposure, loss-per-1%-gap, gap scenarios) crossed with SRM grades and the macro posture, against the current hedge record in the journal. Phase 2 — only if coverage is short for the posture: `tools/calculators/hedge_engine.py` generates three candidate put-spread structures (chain via `alpaca_client.py`, spot via Tiger) scored by coverage-to-cost; the recommended structure enters the plan's hedge block. Skip rule retained: `position_count < 4` → skip and log. A hedge order is order-shaped like any other: it reaches the PM as a plan item and any preview routes through the staging-gatekeeper.
5. **Independent nominations — THE SWARM (explicit mechanics).** One SEPARATE subagent invocation per compiled agent file in `agents/voice-*.md` — the active roster (**11 with the Elder lens, D-51**), never many roles in one context (RB:committee.anti_anchoring). **THE SWARM ALWAYS RUNS — a portfolio breach NEVER skips it (BL-043 / D-65, PM-approved).** A portfolio hard-gate breach (RB:risk.breach — e.g. sector concentration over the 35% gate) caps ONLY what may ADVANCE at committee (steps 9–10); it never skips, delays, or shrinks the swarm. Analysis is not an order: the 11 voices evaluate the full universe on every premarket regardless of book state, and the breach constrains verdicts, not thinking. An empty Nomination Ledger caused by a skipped swarm is an INVALID run (the auditor fails it) — the 18–20 Jul empty-Ledger sessions traced to exactly this deviation, and it must not recur. **DATA TAXONOMY IS MANDATORY (D-53 — the swarm may not run data-starved).** The `universe.json` handed to the voices MUST carry, per name, the full union of the voice data menus (`VOICE_MENUS` in the build) sourced verbatim from the AQE `daily_list` record — the sub-component taxonomy: `elder_5d`, `elder_pattern`, `mp_state`, `mp_accel_state`, `structure_shift`, `sma_distance_pct`, `rvol`, `rs_spy_20d`, `rs_leadership`, `ma_20/50/100/200`, `atr_14d`, the full `bracket` block (incl. `valid`, `atr_fallback_stop`, targets, `rr*`), `lens`/`lens_positive`, `sector_trend_state`, `beta_30d`, and the composites. **A universe reduced to a thin score summary is an INVALID run — the auditor fails it and the orchestrator rebuilds before spawning.** A voice may still only READ its own menu (D-29), but the field must be PRESENT to be read; the 20 Jul dry run fed a stripped 8-field projection and the voices nominated half-blind (they said so) — that must never recur. Per voice: **Claude** — spawn via the Agent/Task tool, prompt = that agent file + the taxonomy-complete universe file + the injected `tools/voice_memory.py render <voice>` block (rolling stats, open picks, STANDING LESSONS D-14; the voice states which lesson applies before nominating), tools disabled; **Kimi** — spawn its subagent definition from `agents/`. Each subagent is a FRESH context: no session, no other voices, no tally. All run in parallel; each returns `nomination.json` (contracts/nomination.schema.json); the orchestrator schema-validates each on receipt. Fewer than the menu-cap with `shortfall_reason` is a valid outcome. **SELF-HEAL ON DECLARED GAPS (D-55 — the agentic-loop principle, no sloppiness).** After receipt, the Chief collects every voice's `data_gaps[]`. For each gap it ROUTES by source per `contracts/field_dictionary.json`: a market/technical field (`ma_20/50/100/200`, `atr_14d`, `rvol`, `rs_spy_20d`, `sma_distance_pct`, `close`, `beta_30d` — anything derivable from prices) is sourced from the **FMP MCP**; an AQE engine-computed field (`sc_momentum`, `structure`, `mp/mp_state`, `elder/elder_5d`, `lens*`, `bracket`, `energy`, `flow`) is sourced by **triggering an AQE re-export** (or reading the fuller AQE record already on disk). The Chief patches the universe record and RE-RUNS the affected voice(s) on the repaired data. Only if a field is genuinely unavailable from both (declared, not guessed) does the name proceed with the gap noted. A voice that declared a gap and was NOT healed before tally is a broken loop — the auditor flags it. This is data-driven design with self-heal: the voice's job is to READ and DECLARE, the Chief's job is to SOURCE; neither invents.
6. **Tally & tier.** Count nominations across the ten files (lens seat counts equally, D-5); stamp `price_at_nomination` into every nomination from the universe file; **also stamp `field_values` (D-20): for each nomination, look up every name in its `fields_cited` in the universe file and record the actual value — this is a deterministic dictionary lookup, no model judgement, and it is what turns each idea from a one-line assertion into a data anchor the PM can inspect.** **Also stamp `quality_flags` (D-39): run `tools/quality_flags.py derive` on each deliberation-set and held name's full AQE record and attach the fired STRENGTH/CAUTION flags (with their source values) — deterministic (law 4), the voices' own restored evaluation vocabulary, SOFT (never a tier/gate change). These travel into the deliberation packet and the plan render.** **DATA BOARD — attach to the consensus tally EVERY DAY (D-60, PM ask).** Immediately after the tally, run `tools/subscore_board.py --universe data/sod/DATE/universe.json --consensus <tally> --out data/sod/DATE/subscore_board.json` — a DETERMINISTIC (law 4, no models, no tokens) view that ranks the SAME universe three ways off the raw AQE sub-scores: (1) detect lens alone (lens_positive), (2) each voice alone (its own menu fields), (3) a data-only TIERING by agreement across three orthogonal axes (voice sub-score breadth · detect strength · elder force). It is a TRANSPARENCY/decision-support attachment, NEVER a gate (D-4/D-52 spirit) — it ranks, it never removes or advances. The board renders beside the consensus picks (step 10) with the board↔consensus divergence called out: names where pure data and the voted tally AGREE (highest-confidence), DATA-ONLY (board Tier-1 the voices under-nominated), and CONSENSUS-ONLY (voted but not data-Tier-1) — that divergence is where the sector/bellwether judgment earns its keep. Deliberation set = RB:committee.deliberation_threshold — ≥2 nominations OR lens-top OR **a single voice at conviction ≥ RB:committee.solo_high_conviction_min (D-37: a strong lone signal is NOT relegated)**; everything else → ranked watch table (each watch row keeps its nomination_count, nominating voices, and 2–3 anchor values — never a bare ticker). ALL nominations → Nomination Ledger.
7. **Event filter (BLOCKING — runs HERE, D-11).** Apply RB:committee.event_filter to the UNION of nominated names only (~30–80 unique), after the tally, before deliberation. Flagged names are marked EVENT-DRIVEN and cannot advance — they stay visible with their flag, never silently dropped. Never run on the full universe (wasteful, wrong order — PM ruling).
8. **Macro & SRM weather + BELLWETHER letters.** Druckenmiller macro brief + SRM read presented as context (RB:srm.role) alongside the deliberation set — after nominations, never before. **Weekly bellwether inputs — the CS Weekly Market Overview and the Crown Macro Letter (PM-supplied) — travel with this context (D-59). They DO NOT gate (weather, per D-4): no name is removed or advanced because a letter said so.** The committee READS them and QUOTES them where a name's read is genuinely supported OR contradicted — e.g. "CS has Financials as the strongest-structure rotation destination (supports the bank adds); Crown flags battered momentum + earnings risk into Alphabet/Tesla/Intel (contradicts chasing extended tech)." A quote must be apt or omitted, never decorative. These are the market's bellwether view, not an oracle: cite as corroboration or tension, PM decides.
9. **Deliberation — spawned, not inline (D-16); Risk sits at the table (D-36).** **Historical-store reconcile FIRST (D-40 — self-heal, before anything anchors on it).** The orchestrator runs `tools/historical_store.py check --list <deliberation-set + held book>`; for every name in `seed_needed` (missing, or stale past the last completed month) it pulls that name's daily history via the FMP MCP (`historical-price-eod-full`, ~6y) and runs `tools/historical_store.py seed <TICKER> --bars <file>` — a deterministic data-plane tool call, NO agent (anti-lasagna), FMP the only source (matches the DoR mandate). A name with < 12 months is recorded `deferred_too_new` and skipped on the daily pass (re-checked monthly via `--with-deferred`), never faked. So no name reaches committee/Risk un-anchored. Primary maintenance of the store is AQE's daily pipeline (Engineering & Change desk, D-40/BL-042); this step is the kernel's safety net. Then the orchestrator has **Risk** produce its anchored read per candidate + held name (ATR/structural/macro/portfolio-fit, sector-exposure impact, sizing-conviction scenarios via `book_sim`, and the post-add **parametric portfolio VaR** via `tools/calculators/var_parametric.py` — single-factor 95% 1-month, D-42, for the VaR gate) — Risk is a VOICE anchored on data, not a downstream calculator. Then it assembles the deliberation-set packet (every nominating voice's case verbatim INCLUDING its `field_values` and the stamped `quality_flags` (D-39), held-book lines, brackets, SRM weather, macro brief, live account snapshot + the Risk lens read) and spawns ONE isolated `agents/committee-desk.md` agent — judgment tier, never run inside the orchestrator's own context. It returns new-idea verdicts (ADVANCE / HOLD-FOR-CONDITIONS / PASS + conviction + mandatory bear case + dissent) AND **`held_verdicts` (D-34): a full deliberation of each HELD position — RUN / TAKE-PARTIAL / TIGHTEN / EXIT from price-vs-ATR-range, structural levels, and runner-vs-weakening momentum — plus a sector-concentration flag**, each with **`data_anchors` (D-20): the decisive field values behind the verdict** → validated against `contracts/committee.schema.json` → `data/sod/DATE/committee.json` (SOD shelf — BL-012). If a portfolio risk gate is breached and unresolved, committee-desk verdicts no ADVANCE at all — that fact leads the plan headline at step 10, same as a stand-down.
10. **Plan assembly.** For held book: the exit actions decided at step 4 (hold/trim/exit/scale-out + trailing-stop raises via `tools/calculators/trailing_stop.py`, D-33 — no longer a dangling promise). For ADVANCE names: bracket verbatim from AQE + size via `tools/calculators/sizing.py` (a wide stop is sized SMALLER, never cut — D-38) + the exact trigger. **BRACKET IS NEVER A GATE (D-52 — reaffirmed after a dry-run breach).** Bracket QUALITY (RR, ATR-distance, risk%) rides as a SOFT flag on the line, not a gate: "wide stop, RR 1.6 (high beta) — momentum call" — the PM sees it and decides. **When AQE's default `bracket.valid = false` (no structural stop auto-passed the 3 gates atr≥1.0 / rr≥2.0 / risk%≤ceiling), the name is NOT disqualified and the orchestrator does NOT report "no valid entry" — it runs a BRACKET EXERCISE:** derive a working bracket from the record AQE already provides — `bracket.atr_fallback_stop` for the stop, the `bracket.targets` (prior-high / fib_1272 / fib_1618 …) for the objectives, and the structural levels (`ma_*`, `fib_*`) — compute the resulting risk% and RR, and carry it on the line flagged `bracket: exercised (fallback stop, RR x.x)`. A no-valid-default-bracket is a "work it" state, not a "reject it" state (PM standing ruling, many times). The auto-invalid reason is shown as context, never as a decision. → **Executive Action Plan** (contracts/plan.schema.json). Every held action, new idea, and watch row carries its `data_anchors` (D-20); any name the Detect lens touched carries `lens_readings` with the lens's actual numbers. **The PHONE RENDER (D-20 anti-black-box):** fixed order (1 headline line → held actions → actionable ideas → **the D-60 data board (detect-lens top · each-voice-top · the 3-axis tier list with the board↔consensus agree/data-only/consensus-only split)** → watch table collapsed); each actionable name is one plain-language line PLUS a short "why (data):" anchor showing the 3–5 decisive numbers in plain labels — e.g. "HBAN — 4 voices, buy over 18.40, stop 17.82 (risk 2.4%), reward:risk 2.8, relative-volume 1.4x" — so the PM decides on data, never on prose alone. **Any fired quality flags (D-39) ride on the line in plain words as soft context — strength flags reinforce ("tight base + squeeze"), CAUTION flags are shown explicitly so the PM sees the warning the voices' own frameworks raised ("caution: bearish divergence", "extended +26% over SMA") — soft, never a filter; a flagged name still appears and is still actionable.** Plain words, no RB keys or raw acronyms, but the NUMBERS are always shown — that is the anchor. Exact mobile template = BL-013, format to be confirmed with the PM. Ready by 16:00.
11. **PM approval by 21:00.** **Missed-approval rule (UX-F3): one reminder at 20:30; no approval by 21:00 → the plan STANDS DOWN as DRAFT — no alerts load, nothing stages, nothing is armed. Silence never trades.** Approve/edit/reject on phone. Approved triggers → AQE intraday alert universe (all voice top-10s + held book load as alert names). For each approved actionable name the orchestrator sends a REQUEST to the staging-gatekeeper skill — the only producer of previews (RB:orders.sole_path). PM personally stages the emitted pre-authorised brackets (RB:orders.phase_1).
12. **Emit run outcome + self-heal wiring (D-45).** On completion emit the phone notification via `tools/notify.py` — `run_ok` with the plan headline (names advanced, VaR, gate state) on success, or `run_fail` (the unmistakable red page) if the phase stood down. Throughout the ladder below, **PAGE = `tools/notify.py run_fail`** (order-blind). Before standing down on a **transient** data failure (a feed/PTJ pull error — NOT a tripwire BLOCK), the orchestrator first runs `tools/self_heal.py premarket --failure <type>` (bounded retry/reseed, RB:self_heal): it heals silently and continues if it can, else escalates with the manual fix (`/recover`). A tripwire BLOCK or hard-gate breach is a **gate** — stand down, never healed. The T-minus pre-run heartbeat (RB:notifications.pre_run_minutes) is fired by the scheduler, not here.

## ON FAILURE (RB:exceptions — the ladder governs; every event writes an exception record to data/sod/DATE/exceptions/)
- Feed missing/stale, or tripwire BLOCK, or universe screen cannot run → **STAND DOWN the whole phase**: no plan, no alerts, nothing armed; PAGE. Held book stays protected by broker-side stops. Record the day as stood-down; post-market still runs.
- A voice returns nothing/invalid → re-spawn ONCE → still bad: proceed with the rest (minimum 8), tally shows the empty seats, auditor marks INCOMPLETE; morning summary.
- Hedge tools fail → plan ships WITHOUT the hedge block, flagged in the headline; morning summary.
- Deliberation cannot complete → no name gets ADVANCE (watch-table only); held actions still ship; morning summary.
- Plan fails its contract at assembly → do NOT deliver a broken plan; STAND DOWN + PAGE.
