# PROCESS: PREMARKET (weekdays; plan ready 16:00 SGT, PM approval by 21:00 — RB:schedule)
**Desk sequence (D-26/D-32):** the Chief adopts **Research** (steps 1–9: universe, swarm, tally, event filter, weather, deliberation) → **Risk** (step 10 sizing + gates) → **PM approval** (step 11) → **Execution** (step 11 staging requests). Physical move to `orchestration/` = BL-033. Voices work in isolation at step 5. No numbers here — all thresholds are RB: keys.
**Model note (D-16):** you, the orchestrator running this skill, are control plane — RB:model_tiers.control. Your job is sequencing, tool calls, and contract validation, never analysis. Every step that needs real judgment (the swarm at step 5, deliberation at step 9) is delegated to a pinned judgment-tier agent — RB:model_tiers.judgment, baked into that agent's own compiled file. Don't reason hard here; spawn, validate, move on.

0. **Preflight (D-49).** Run `tools/preflight.py`. If `GITHUB_PAT` is MISSING, the post-market push will fail — page the PM to paste it into `config/.env` (the tool prints the exact one-liner) and continue the read/compute work regardless (the token is only needed at the post-market commit, not to run premarket). Never block the plan on it; never fabricate a token.
1. **Freshness check — confirm the gate, do not re-implement it (D-83).** Run `python3 tools/phase_gate.py check --json` and read the exit code. **0 = READY → proceed to step 2.** Anything else → **STOP HERE and stand down**, paging with the check's own `reasons` verbatim: 1 (NOT_READY, post-market or the AQE export is merely late) or 2 (BLOCKED, post-market ran and failed). This is a belt-and-braces re-check, not the primary gate — the primary gate is the `phase_zero` skill, which runs this same command on its own cheap scheduled task and is the only thing that fires this build. If the gate is not green here, something changed between the fire and now, or this session was started by hand out of sequence; either way the answer is stand down, never "proceed and see." **Do not re-derive freshness from file mtimes, do not eyeball the export date, do not proceed on a partial** — one command, one exit code. The full RB:data_sources.staleness rule is implemented inside the tool; a second copy of it here is exactly the drift this decision removes.
2. **Universe build (single source — D-81).** Run `tools/universe_build.py` → `data/sod/DATE/universe.json` (the only file voices nominate from). **The AQE daily export IS the fully-scored universe (D-66); FMP feeds AQE upstream, so the kernel does NOT re-screen FMP** — `tools/universe_screen.py` is retired to a standalone FMP tool, no longer on the premarket path (this ended the 3-shapes-in-3-days drift). The builder emits ONE fixed, schema-enforced shape (`contracts/universe.schema.json`), each name TRIMMED to the consumed field set (no more 97-field byte-copy of the export), PLUS a `near_misses` list (D-37) — names just below the alert floor, SURFACED in the plan so the committee/PM can revive one, never a silent early cut.
3. **AQE pull — from the Drive "AQE" folder, with BOUNDED RETRY before any stand-down (D-66 + D-70).** The AQE engine writes `aqe_daily_export.json` to the Google Drive folder named **"AQE"** (id `1CJMoI19Zf_ZFeU5_5uhW9l92IB8fVger`) on its daily run (observed timing: starts ~08:30 SGT, exports ~08:43 SGT, finishes ~08:44 SGT — a ~14-min job, well inside premarket's 10:00 SGT fire, a ~75-min buffer) — that folder IS the feed, and a fresh scheduled session already has the Google Drive connector, so the kernel PULLS it directly (no PC-side git push, no assumption it is pre-staged on disk). Procedure: search the "AQE" folder for `aqe_daily_export.json`, download it to `output/aqe_daily_export.json`, and check freshness — the export's internal `date` must be today (T-1 at the oldest, PM-acknowledged per RB:data_sources.staleness). **On MISSING/STALE, this is `feed_pull` — the SAME transient failure class as everywhere else in this system (RB:self_heal), and D-66's original text wrongly short-circuited straight to stand-down instead of using the established bounded-retry doctrine — corrected here (D-70).** Retry per `tools/self_heal.py <loop> --failure feed_pull --max-retries 3` policy: re-check at +5 min, +10 min, +10 min (~25 min worst case, still 4.5h+ before the 16:00 SGT plan deadline) — AQE running a few minutes behind on any given day self-heals silently, no page, no PM action. **Only if STILL missing/stale after 3 retries** does the phase STAND DOWN with a page (`tools/notify.py run_fail --loop premarket --step "AQE export pull" --last-good <last known-good date>`) — this is a genuine AQE-side failure, not a timing hiccup, and it does NOT proceed on nothing (the 18–20 Jul empty-Ledger root cause — the export never reached the workspace). **The page states the manual fix plainly (D-70, PM: "minimum is I am notified to resolve manually, aka trigger a fixed run"): once AQE's pipeline is confirmed complete (PM checks/kicks it on their box, or simply waits it out), tell Claude "rerun premarket" in any live session — that re-fires the scheduled premarket trigger on demand via `fire_trigger`, no separate automation, no silent auto-retry of AQE itself (which the kernel does not control and never touches).** Once fresh: validate against `contracts/aqe_export.schema.json`; run `tools/tripwires.py` (blocks on anomaly). Extract the working read only — full subcomponents stay on disk until a name reaches deliberation. (The intraday `aqe_ma_scan.json` / alert inbox is a separate, lesser feed for the market-hours `/loop`; keep it in the same "AQE" folder so there is ONE feed location.)
4. **Held book FIRST — exits before entries (D-33).** **Close the held-book loop HERE, right after step 3's fresh AQE pull — this is Operation 4 of the `print-trade-journal` skill (PM: "once AQE is run in premarket, the procedure also updates the file with new levels, not overwrite"):** run `tools/held_book_refresh.py refresh --journal data/journal/aegis_journal_YYYY-MM-DD.json --export output/aqe_daily_export.json` — a targeted per-ticker MERGE that overwrites only `aqe_snapshot` + `aqe_snapshot_as_of` on each held name, using TODAY's export. It never touches the execution-truth fields post-market already wrote this morning — this is the update, not an overwrite, the PM asked for. A held name absent from today's export keeps its existing (now-stale) snapshot and is flagged `not_in_todays_export` in `review_flags`, never silently blanked. This is what closes the loop: post-market's next run will read THIS refreshed snapshot forward, so the portfolio metrics it computes tomorrow morning reflect today's AQE, not last week's. The Aegis held book is then read from that same **Aegis journal file** (`data/journal/aegis_journal_YYYY-MM-DD.json`, D-84 — the sole book of record; the old separate Drive PTJ copy is retired) — the one source already filtered to the AEGIS sub-fund (D-17/D-21), NOT the raw broker account nor the AQE export's `held_positions` (which mismatched the live account 18 Jul — BL-024). Before any new idea is sized, the Chief adopts **Risk** and runs the **exits skill** (`desks/risk/exits`, `trailing_stop.py`) for the MATH — **this is now the ONLY place trailing stops are recomputed (D-84): post-market used to run a duplicate nightly pass, but it ran BEFORE AQE's export existed each morning, so it was computing off yesterday's structure and pushing a possibly-wrong TIGHTEN_STOP request off stale data — removed, not moved, because this step already does the same job correctly, right after step 3's fresh AQE pull.** Its `aqe_operative_stop` input comes from the `bracket` field this step's held-book refresh just wrote into each position's `aqe_snapshot` (D-85) — one source, not a second in-memory read of the export. recompute each trailing stop (mechanical FLOOR — breakeven→structure ratchet, never lowers), compute per-sector exposure (RB:risk.gates.sector_exposure), and identify rotation candidates. **Then run Operation 5 of `print-trade-journal`** — `tools/held_book_refresh.py stop-update --journal data/journal/aegis_journal_YYYY-MM-DD.json --stops <ticker: new-stop map>` — to write each new floor into `stop_reference` and recompute `stop_match` against the broker's live stop. A MISMATCH right here is normal (the broker order usually hasn't been staged yet), flagged in `review_flags`, never a reason to stop. The held JUDGMENT — RUN / TAKE-PARTIAL / TIGHTEN / EXIT per name, from price-vs-ATR-range + structural levels + runner-vs-weakening — is the **committee's**, produced at step 9 (D-34); step 10 combines the committee read with the mechanical floor so the **PM decides partial-vs-run**. **dynCap refresh (D-41 — mark-to-market): because the PTJ is already loaded here with open positions marked to price, the orchestrator runs `tools/dyncap_ledger.py update <ptj>` NOW — dynCap = allocation + realised + unrealised = current Aegis equity, so every size today is against what is actually held (it de-sizes in drawdown). This is the daily refresh; a stale mark is never used.** Freed/protected capital and the refreshed dynCap set what is available for new sizing. Within this step the **hedge assessment** runs (BL-007, wired 18 Jul): Phase 1 — coverage matrix from the AQE `held_book` (beta-adjusted exposure, loss-per-1%-gap, gap scenarios) crossed with SRM grades and the macro posture, against the current hedge record in the journal. Phase 2 — only if coverage is short for the posture: `tools/calculators/hedge_engine.py` generates three candidate put-spread structures (chain via `alpaca_client.py`, spot via Tiger) scored by coverage-to-cost; the recommended structure enters the plan's hedge block. Skip rule retained: `position_count < 4` → skip and log. A hedge order is order-shaped like any other: it reaches the PM as a plan item and any preview routes through the staging-gatekeeper.
5. **Independent nominations — THE SWARM (explicit mechanics).** One SEPARATE subagent invocation per compiled agent file in `agents/voice-*.md` — the active roster (**11 with the Elder lens, D-51**), never many roles in one context (RB:committee.anti_anchoring). **THE SWARM ALWAYS RUNS — a portfolio breach NEVER skips it (BL-043 / D-65, PM-approved).** A portfolio hard-gate breach (RB:risk.breach — e.g. sector concentration over the 35% gate) caps ONLY what may ADVANCE at committee (steps 9–10); it never skips, delays, or shrinks the swarm. Analysis is not an order: the 11 voices evaluate the full universe on every premarket regardless of book state, and the breach constrains verdicts, not thinking. An empty Nomination Ledger caused by a skipped swarm is an INVALID run (the auditor fails it) — the 18–20 Jul empty-Ledger sessions traced to exactly this deviation, and it must not recur. **DATA TAXONOMY IS MANDATORY (D-53 — the swarm may not run data-starved).** The `universe.json` handed to the voices MUST carry, per name, the full union of the voice data menus (`VOICE_MENUS` in the build) sourced verbatim from the AQE `daily_list` record — the sub-component taxonomy: `elder_5d`, `elder_pattern`, `mp_state`, `mp_accel_state`, `structure_shift`, `sma_distance_pct`, `rvol`, `rs_spy_20d`, `rs_leadership`, `ma_20/50/100/200`, `atr_14d`, the full `bracket` block (incl. `valid`, `atr_fallback_stop`, targets, `rr*`), `lens`/`lens_positive`, `sector_trend_state`, `beta_30d`, and the composites. **A universe reduced to a thin score summary is an INVALID run — the auditor fails it and the orchestrator rebuilds before spawning.** A voice may still only READ its own menu (D-29), but the field must be PRESENT to be read; the 20 Jul dry run fed a stripped 8-field projection and the voices nominated half-blind (they said so) — that must never recur. Per voice: **Claude** — spawn via the Agent/Task tool, prompt = that agent file + the taxonomy-complete universe file + the injected `tools/voice_memory.py render <voice>` block (rolling stats, open picks, STANDING LESSONS D-14; the voice states which lesson applies before nominating), tools disabled; **Kimi** — spawn its subagent definition from `agents/`. Each subagent is a FRESH context: no session, no other voices, no tally. All run in parallel; each returns `nomination.json` (contracts/nomination.schema.json); the orchestrator schema-validates each on receipt. Fewer than the menu-cap with `shortfall_reason` is a valid outcome. **SELF-HEAL ON DECLARED GAPS (D-55 — the agentic-loop principle, no sloppiness).** After receipt, the Chief collects every voice's `data_gaps[]`. For each gap it ROUTES by source per `contracts/field_dictionary.json`: a market/technical field (`ma_20/50/100/200`, `atr_14d`, `rvol`, `rs_spy_20d`, `sma_distance_pct`, `close`, `beta_30d` — anything derivable from prices) is sourced from the **FMP MCP**; an AQE engine-computed field (`sc_momentum`, `structure`, `mp/mp_state`, `elder/elder_5d`, `lens*`, `bracket`, `energy`, `flow`) is sourced by **triggering an AQE re-export** (or reading the fuller AQE record already on disk). The Chief patches the universe record and RE-RUNS the affected voice(s) on the repaired data. Only if a field is genuinely unavailable from both (declared, not guessed) does the name proceed with the gap noted. A voice that declared a gap and was NOT healed before tally is a broken loop — the auditor flags it. This is data-driven design with self-heal: the voice's job is to READ and DECLARE, the Chief's job is to SOURCE; neither invents.
6. **Tally & tier.** Count nominations across the ten files (lens seat counts equally, D-5); stamp `price_at_nomination` into every nomination from the universe file; **also stamp `field_values` (D-20): for each nomination, look up every name in its `fields_cited` in the universe file and record the actual value — this is a deterministic dictionary lookup, no model judgement, and it is what turns each idea from a one-line assertion into a data anchor the PM can inspect.** **Also stamp `quality_flags` (D-39): run `tools/quality_flags.py derive` on each deliberation-set and held name's full AQE record and attach the fired STRENGTH/CAUTION flags (with their source values) — deterministic (law 4), the voices' own restored evaluation vocabulary, SOFT (never a tier/gate change). These travel into the deliberation packet and the plan render.** **DATA BOARD — attach to the consensus tally EVERY DAY (D-60, PM ask).** Immediately after the tally, run `tools/subscore_board.py --universe data/sod/DATE/universe.json --consensus <tally> --out data/sod/DATE/subscore_board.json` — a DETERMINISTIC (law 4, no models, no tokens) view that ranks the SAME universe three ways off the raw AQE sub-scores: (1) detect lens alone (lens_positive), (2) each voice alone (its own menu fields), (3) a data-only TIERING by agreement across three orthogonal axes (voice sub-score breadth · detect strength · elder force). It is a TRANSPARENCY/decision-support attachment, NEVER a gate (D-4/D-52 spirit) — it ranks, it never removes or advances. The board renders beside the consensus picks (step 10) with the board↔consensus divergence called out: names where pure data and the voted tally AGREE (highest-confidence), DATA-ONLY (board Tier-1 the voices under-nominated), and CONSENSUS-ONLY (voted but not data-Tier-1) — that divergence is where the sector/bellwether judgment earns its keep. **PIPELINE CARRY-OVER — the ledger's daily half comes back in HERE (D-83).** Run `python3 tools/pipeline_ledger.py active --classification daily_reconsider --json`. Every active row is a name a previous committee explicitly asked to keep alive. Each one joins the deliberation set as a **CARRY-OVER entry** carrying its `case_snapshot` verbatim — the case that committee made — plus its `origin_date` so today's committee can see how long it has been waiting. **It is re-scored fresh from today's universe file like any other candidate; the snapshot is context, never a score and never a shortcut past the threshold below.** A carry-over whose ticker is NOT in today's universe cannot be deliberated on data — it goes to the watch table with its snapshot and a "not in today's universe" note, and stays in the ledger until its TTL. Carry-overs do not consume a nomination slot and do not inflate `nomination_count`. Deliberation set = RB:committee.deliberation_threshold — ≥2 nominations OR lens-top OR **a single voice at conviction ≥ RB:committee.solo_high_conviction_min (D-37: a strong lone signal is NOT relegated)** OR **an active `daily_reconsider` carry-over**; everything else → ranked watch table (each watch row keeps its nomination_count, nominating voices, and 2–3 anchor values — never a bare ticker). ALL nominations → Nomination Ledger.
6b. **CONVICTION FUNNEL — the three-axis daily shortlist (D-78, PM: "data driven, lens and consensus driven… concise summary highlighting contradictory or positive overlaps… always start from approx 10–15 names to filter down into a high conviction plan").** After the tally and the event filter, run `tools/conviction_funnel.py build --tally data/sod/DATE/tally.json --export output/aqe_daily_export.json --event-blocked <event-driven names> --out data/sod/DATE/conviction_funnel.json` — DETERMINISTIC (law 4, no model). It grades every nominated name S/M/W on three axes, but in a DELIBERATE ORDER (D-79, PM: "data but lens first before we anchor on voices advisory"): **DATA** (the 8-lane casting mat, D-77 — momentum-arrival depth) and **LENS** (the 6-lens detect count) are the PRIMARY, mechanical axes; **CONSENSUS** (voices: nomination count + avg conviction) is an ADVISORY overlay, never the entry ticket. It produces: (1) a **SHORTLIST of ~10–15 names whose entry is MECHANICAL — DATA strong OR LENS strong** — ranked by lanes+detect first (votes only a tiebreak), each tagged **TRIPLE** (data+lens+voices all agree — highest), **CONFIRMED** (data/lens-led AND the swarm backed it), or **DATA_LED** (data/lens-led but voices advisory-silent — the swarm under-nominated it, promoted into the shortlist anyway because data leads). This is the high-conviction start-point for deep deliberation. (2) **CONTRADICTIONS TO RESOLVE** — `consensus_only`: names VOTED well (≥ RB:conviction_funnel.cons_strong_votes) but where DATA+LENS do NOT confirm (e.g. DINO 4 votes/2 lanes, and even the top-headline-momentum UNP/CSX 4 votes/3 lanes/0 lens on 21 Jul) → the voices are advisory only here, so the committee must explicitly rule fresh-or-stale, run or drop. (The former 'data-strong-but-under-nominated missed runner' set is now PROMOTED into the shortlist as DATA_LED rather than sidelined — data leads.) This is TRANSPARENCY/decision-support, never a gate (D-4/D-52) — it focuses and frames deliberation, it never removes or advances a name on its own. The concise `summary` string is surfaced in the plan render. **The committee (step 9) deliberates the shortlist AND must explicitly RESOLVE each contradiction (run or drop, with reason) — a contradiction left unaddressed is an incomplete deliberation.** Complements the D-60 data board (which stays); the funnel is the momentum-lane-aware convergence view that drives the ~10–15 name start-point.

8. **Macro & SRM weather + BELLWETHER letters.** Druckenmiller macro brief + SRM read presented as context (RB:srm.role) alongside the deliberation set — after nominations, never before. **Weekly bellwether inputs — the CS Weekly Market Overview and the Crown Macro Letter (PM-supplied) — travel with this context (D-59). 9. **Deliberation — spawned, not inline (D-16); Risk sits at the table (D-36).** **SELECTION DOCTRINE (LOCKED, D-80): DATA leads · LENS seconds · VOICES corroborate or challenge → consensus for HIGH CONVICTION.** The committee deliberates the step-6b DATA+LENS-led shortlist and the flagged contradictions: for each name the voices either CORROBORATE (add their case + conviction), stay silent (mechanical-only, note it), or CHALLENGE (dissent / bear case, or defend a voted name the mechanicals didn't confirm). HIGH CONVICTION = mechanical confirmation (data/lens) AND voice corroboration; a mechanically-strong name the voices challenge, or a voted name the mechanicals don't confirm, must be explicitly RESOLVED (run or drop, with reason), never auto-advanced. Voices corroborate or challenge — they never carry a name on votes alone. **Historical-store reconcile FIRST (D-40 — self-heal, before anything anchors on it).** The orchestrator runs `tools/historical_store.py check --list <deliberation-set + held book>`; for every name in `seed_needed` (missing, or stale past the last completed month) it pulls that name's daily history via the FMP MCP (`historical-price-eod-full`, ~6y) and runs `tools/historical_store.py seed <TICKER> --bars <file>` — a deterministic data-plane tool call, NO agent (anti-lasagna), FMP the only source (matches the DoR mandate). A name with < 12 months is recorded `deferred_too_new` and skipped on the daily pass (re-checked monthly via `--with-deferred`), never faked. So no name reaches committee/Risk un-anchored. Primary maintenance of the store is AQE's daily pipeline (Engineering & Change desk, D-40/BL-042); this step is the kernel's safety net. Then the orchestrator has **Risk** produce its anchored read per candidate + held name (ATR/structural/macro/portfolio-fit, sector-exposure impact, sizing-conviction scenarios via `book_sim`, and the post-add **parametric portfolio VaR** via `tools/calculators/var_parametric.py` — single-factor 95% 1-month, D-42, for the VaR gate) — Risk is a VOICE anchored on data, not a downstream calculator. Then it assembles the deliberation-set packet (every nominating voice's case verbatim INCLUDING its `field_values` and the stamped `quality_flags` (D-39), held-book lines, brackets, SRM weather, macro brief, live account snapshot + the Risk lens read) and spawns ONE isolated `agents/committee-desk.md` agent — judgment tier, never run inside the orchestrator's own context. It returns new-idea verdicts (ADVANCE / HOLD-FOR-CONDITIONS / PASS + conviction + mandatory bear case + dissent) AND **`held_verdicts` (D-34): a full deliberation of each HELD position — RUN / TAKE-PARTIAL / TIGHTEN / EXIT from price-vs-ATR-range, structural levels, and runner-vs-weakening momentum — plus a sector-concentration flag**, each with **`data_anchors` (D-20): the decisive field values behind the verdict** → validated against `contracts/committee.schema.json` → `data/sod/DATE/committee.json` (SOD shelf — BL-012). **File the Pipeline Ledger HERE, immediately (D-83/D-84 — moved from post-market, PM: "we file immediately after premarket... it eventually feeds into intraday monitoring, things on list but missed during premarket").** The moment `committee.json` is written, run `tools/pipeline_ledger.py persist --committee data/sod/DATE/committee.json --date DATE`. This is filing only, no new judgement — the committee already decided `ledger_proposal` per verdict at the moment above; this just writes it to disk. Filing here (not waiting for tonight's post-market) is what lets a `trigger_silent` name join step 10's List P THE SAME DAY, so the market-hours sweep can watch it that same afternoon instead of a full session late. If a portfolio risk gate is breached and unresolved, committee-desk verdicts no ADVANCE at all — that fact leads the plan headline at step 10, same as a stand-down.
9a. **Reactive/off-cycle deliberation — sector-sleeve apples-to-apples.** Any candidate sent to committee OUTSIDE the once-daily swarm cadence (a PM ad hoc request, a live catalyst, a re-look after a thin-conviction result) is NEVER deliberated in isolation. The orchestrator first pulls every OTHER verdict already on record for that name's sector/sleeve from the day's `committee.json` (ADVANCE, HOLD-FOR-CONDITIONS, AND PASS — dump the full `verdicts[]` array, never a ticker-filtered grep; a partial read here (checking only the requested tickers) produced an incomplete picture once and must not recur) and hands the committee-desk spawn the full sleeve side by side. The verdict on the new candidate must say explicitly whether it is ADDITIVE (fills a gap the sleeve doesn't already cover) or REDUNDANT (a same-thesis name where a stronger corroborated case already occupies the slot) — "technically fine" is not "worth a second slot." **Live-catalyst re-contextualization:** when a candidate's case rests on a fresh real-world event (a geopolitical shock, a surprise data print, a Houthi-blockade-style catalyst), verify the event actually happened and is still live via WebSearch before treating it as an input — then re-read the name's static metrics (rvol, sc_momentum, structure) against the ACTUAL live tape, not the pre-catalyst snapshot; a metric computed before the catalyst broke is stale context, not current signal.
9b. **Capital/quality separation is absolute — PM standing ruling: "You shouldn't size or pick trades based on my capital. That is my call to leverage or not based on quality of the trade idea."** The committee-desk verdict (ADVANCE / HOLD-FOR-CONDITIONS / PASS) is decided ONLY on trade-quality grounds — framework case, bracket, risk lens, quality flags. Capital/dynCap availability, broker-side execution constraints (an IBKR 30-day compliance hold blocking an outright SELL, margin segregation, or any other "can we actually execute this" fact) NEVER enters the verdict itself and never downgrades or blocks an ADVANCE. It is reported as a SEPARATE, clearly labeled line — e.g. "⚠ execution note: IBM is under IBKR 30-day compliance hold — this EXIT cannot be placed yet; do not assume the capital it would free is available for sizing" — directly under the verdict, never folded into it. Before any plan step assumes a held-book exit frees capital for new sizing, the orchestrator checks the position against any known broker-side hold/restriction and foots the assumption if one applies.
9c. **Trust but verify on subagent writes.** A committee-desk (or any subagent) claim of "written to `data/sod/DATE/committee.json`" is NOT accepted on its word — the orchestrator runs `git status --short` and/or re-reads the file directly to confirm the write actually landed before telling the PM the record is persisted. A subagent's self-report of a completed file write has been wrong before; treat every such claim as unverified until checked.
10. **Plan assembly.** For held book: the exit actions decided at step 4 (hold/trim/exit/scale-out + trailing-stop raises via `tools/calculators/trailing_stop.py`, D-33 — no longer a dangling promise). For ADVANCE names: bracket verbatim from AQE + size via `tools/calculators/sizing.py` (a wide stop is sized SMALLER, never cut — D-38) + the exact trigger. **BRACKET IS NEVER A GATE (D-52 — reaffirmed after a dry-run breach).** Bracket QUALITY (RR, ATR-distance, risk%) rides as a SOFT flag on the line, not a gate: "wide stop, RR 1.6 (high beta) — momentum call" — the PM sees it and decides. **When AQE's default `bracket.valid = false` (no structural stop auto-passed the 3 gates atr≥1.0 / rr≥2.0 / risk%≤ceiling), the name is NOT disqualified and the orchestrator does NOT report "no valid entry" — it runs a BRACKET EXERCISE:** derive a working bracket from the record AQE already provides — `bracket.atr_fallback_stop` for the stop, the `bracket.targets` (prior-high / fib_1272 / fib_1618 …) for the objectives, and the structural levels (`ma_*`, `fib_*`) — compute the resulting risk% and RR, and carry it on the line flagged `bracket: exercised (fallback stop, RR x.x)`. ## ON FAILURE (RB:exceptions — the ladder governs; every event writes an exception record to data/sod/DATE/exceptions/)
- Feed missing/stale, or tripwire BLOCK, or universe screen cannot run → **STAND DOWN the whole phase**: no plan, no alerts, nothing armed; PAGE. Held book stays protected by broker-side stops. Record the day as stood-down; post-market still runs.
- A voice returns nothing/invalid → **first check the failure text against `tools/self_heal.py`'s `detect_usage_limit()` (D-72).** A match (a session/rate/weekly-cap signature, not a content problem) is a DIFFERENT failure from a voice simply nominating badly: run `tools/self_heal.py premarket --failure usage_limit` (capacity class, no auto-retry — retrying now just re-hits the same ceiling) and PAGE with the D-72 manual fix (wait for the account's usage window to reset, then "rerun premarket") — this is a Claude Max-plan capacity ceiling, not a data or voice-quality issue, and must not be mislabeled INCOMPLETE. No match → the ordinary path: re-spawn ONCE → still bad: proceed with the rest (minimum 8), tally shows the empty seats, auditor marks INCOMPLETE; morning summary. The SAME usage_limit check applies to the committee-desk spawn at step 9 (a single opus call, same ceiling risk) — a failure there pages the same way rather than being treated as "deliberation cannot complete" below.
- Hedge tools fail → plan ships WITHOUT the hedge block, flagged in the headline; morning summary.
- Deliberation cannot complete → no name gets ADVANCE (watch-table only); held actions still ship; morning summary.
- Plan fails its contract at assembly → do NOT deliver a broken plan; STAND DOWN + PAGE.
