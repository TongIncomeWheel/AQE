# PROCESS: PREMARKET (weekdays; plan ready 16:00 SGT, PM approval by 21:00 — RB:schedule)
Owner: Premarket Orchestrator. Voices work in isolation at step 5. No numbers here — all thresholds are RB: keys.

1. **Freshness check.** Journal current? AQE export dated today (RB:data_sources.staleness)? If stale → fix/notify first, do not proceed silently.
2. **Universe build.** Run `tools/universe_screen.py` (RB:universe.screen) → `data/sod/DATE/universe.json` (shelf layout). This file is the only universe any voice sees.
3. **AQE pull.** Fetch daily export; validate against `contracts/aqe_export.schema.json`; run `tools/tripwires.py` (blocks on anomaly). Extract the working read only — full subcomponents stay on disk until a name reaches deliberation.
4. **Held book = same path, plus the hedge check.** Held positions enter the same scoring pull and the same deliberation as new candidates (no special held path). Within this step the **hedge assessment** runs (BL-007, wired 18 Jul): Phase 1 — coverage matrix from the AQE `held_book` (beta-adjusted exposure, loss-per-1%-gap, gap scenarios) crossed with SRM grades and the macro posture, against the current hedge record in the journal. Phase 2 — only if coverage is short for the posture: `tools/calculators/hedge_engine.py` generates three candidate put-spread structures (chain via `alpaca_client.py`, spot via Tiger) scored by coverage-to-cost; the recommended structure enters the plan's hedge block. Skip rule retained: `position_count < 4` → skip and log. A hedge order is order-shaped like any other: it reaches the PM as a plan item and any preview routes through the staging-gatekeeper.
5. **Independent nominations — THE SWARM (explicit mechanics).** Ten SEPARATE subagent invocations, one per compiled agent file in `agents/voice-*.md` — never ten roles in one context (RB:committee.anti_anchoring). Per voice: **Claude** — spawn via the Agent/Task tool, prompt = that agent file + the universe file + the injected `nomination_ledger.py report --voice X` output, tools disabled; **Kimi** — spawn its subagent definition from `agents/`. Each subagent is a FRESH context: no session, no other voices, no tally. All ten run in parallel; each returns `nomination.json` (contracts/nomination.schema.json); the orchestrator schema-validates each on receipt. Fewer than 10 with `shortfall_reason` is a valid outcome.
6. **Tally & tier.** Count nominations across the ten files (lens seat counts equally, D-5); stamp `price_at_nomination` into every nomination from the universe file; deliberation set = RB:committee.deliberation_threshold; everything else → ranked watch table. ALL nominations → Nomination Ledger.
7. **Event filter (BLOCKING — runs HERE, D-11).** Apply RB:committee.event_filter to the UNION of nominated names only (~30–80 unique), after the tally, before deliberation. Flagged names are marked EVENT-DRIVEN and cannot advance — they stay visible with their flag, never silently dropped. Never run on the full universe (wasteful, wrong order — PM ruling).
8. **Macro & SRM weather.** Druckenmiller macro brief + SRM read presented as context (RB:srm.role) alongside the deliberation set — after nominations, never before.
9. **Deliberation.** Single shared session on the deliberation set only: each nominating voice states its case, mandatory bear case (RB:committee.bear_case_mandatory), unanimity challenge if triggered. Output per name: ADVANCE / HOLD-FOR-CONDITIONS / PASS + conviction + recorded dissent → `data/committee/committee_YYYY-MM-DD.json`.
10. **Plan assembly.** For held book: hold/trim/exit + stop adjustments (trailing per calculators). For ADVANCE names: bracket verbatim from AQE + size via `tools/calculators/sizing.py` + the exact trigger that makes it actionable. → **Executive Action Plan** (contracts/plan.schema.json) + the PHONE RENDER: fixed order (1 headline line → held actions → actionable ideas ≤1 line each → watch table collapsed), plain words only — no RB keys, no acronyms, "risk 8.5% > your 8% ceiling" not raw fields. Ready by 16:00.
11. **PM approval by 21:00.** **Missed-approval rule (UX-F3): one reminder at 20:30; no approval by 21:00 → the plan STANDS DOWN as DRAFT — no alerts load, nothing stages, nothing is armed. Silence never trades.** Approve/edit/reject on phone. Approved triggers → AQE intraday alert universe (all voice top-10s + held book load as alert names). For each approved actionable name the orchestrator sends a REQUEST to the staging-gatekeeper skill — the only producer of previews (RB:orders.sole_path). PM personally stages the emitted pre-authorised brackets (RB:orders.phase_1).

## ON FAILURE (RB:exceptions — the ladder governs; every event writes an exception record to data/sod/DATE/exceptions/)
- Feed missing/stale, or tripwire BLOCK, or universe screen cannot run → **STAND DOWN the whole phase**: no plan, no alerts, nothing armed; PAGE. Held book stays protected by broker-side stops. Record the day as stood-down; post-market still runs.
- A voice returns nothing/invalid → re-spawn ONCE → still bad: proceed with the rest (minimum 8), tally shows the empty seats, auditor marks INCOMPLETE; morning summary.
- Hedge tools fail → plan ships WITHOUT the hedge block, flagged in the headline; morning summary.
- Deliberation cannot complete → no name gets ADVANCE (watch-table only); held actions still ship; morning summary.
- Plan fails its contract at assembly → do NOT deliver a broken plan; STAND DOWN + PAGE.
