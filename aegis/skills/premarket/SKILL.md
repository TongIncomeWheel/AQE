# PROCESS: PREMARKET (weekdays; plan ready 16:00 SGT, PM approval by 21:00 — RB:schedule)
**Desk sequence (D-26/D-32):** the Chief adopts **Research** (steps 1–9: universe, swarm, tally, event filter, weather, deliberation) → **Risk** (step 10 sizing + gates) → **PM approval** (step 11) → **Execution** (step 11 staging requests). Physical move to `orchestration/` = BL-033. Voices work in isolation at step 5. No numbers here — all thresholds are RB: keys.
**Model note (D-16):** you, the orchestrator running this skill, are control plane — RB:model_tiers.control. Your job is sequencing, tool calls, and contract validation, never analysis. Every step that needs real judgment (the swarm at step 5, deliberation at step 9) is delegated to a pinned judgment-tier agent — RB:model_tiers.judgment, baked into that agent's own compiled file. Don't reason hard here; spawn, validate, move on.

0. **Preflight (D-49).** Run `tools/preflight.py`. If `GITHUB_PAT` is MISSING, the post-market push will fail — page the PM to paste it into `config/.env` (the tool prints the exact one-liner) and continue the read/compute work regardless (the token is only needed at the post-market commit, not to run premarket). Never block the plan on it; never fabricate a token.
1. **Freshness check.** Journal current? AQE export dated today (RB:data_sources.staleness)? If stale → fix/notify first, do not proceed silently.
2. **Universe build.** Run `tools/universe_screen.py` (RB:universe.screen) → `data/sod/DATE/universe.json` (the only file voices nominate from) PLUS a `near_misses` list (D-37, RB:universe.near_miss) — names just outside the screen (within band on EMA/vol). Near-misses are NOT nominated, but they are SURFACED in the plan so the committee/PM can revive one — the screen is no longer a silent early cut.
3. **AQE pull.** Fetch daily export; validate against `contracts/aqe_export.schema.json`; run `tools/tripwires.py` (blocks on anomaly). Extract the working read only — full subcomponents stay on disk until a name reaches deliberation.
4. **Held book FIRST — exits before entries (D-33).** The Aegis held book is read from the latest **Aegis PTJ file** — the one source already filtered to the AEGIS sub-fund (D-17/D-21), NOT the raw broker account nor the AQE export's `held_positions` (which mismatched the live account 18 Jul — BL-024). Before any new idea is sized, the Chief adopts **Risk** and runs the **exits skill** (`desks/risk/exits`, `trailing_stop.py`) for the MATH: recompute each trailing stop (mechanical FLOOR — breakeven→structure ratchet, never lowers), compute per-sector exposure (RB:risk.gates.sector_exposure), and identify rotation candidates. The held JUDGMENT — RUN / TAKE-PARTIAL / TIGHTEN / EXIT per name, from price-vs-ATR-range + structural levels + runner-vs-weakening — is the **committee's**, produced at step 9 (D-34); step 10 combines the committee read with the mechanical floor so the **PM decides partial-vs-run**. **dynCap refresh (D-41 — mark-to-market): because the PTJ is already loaded here with open positions marked to price, the orchestrator runs `tools/dyncap_ledger.py update <ptj>` NOW — dynCap = allocation + realised + unrealised = current Aegis equity, so every size today is against what is actually held (it de-sizes in drawdown). This is the daily refresh; a stale mark is never used.** Freed/protected capital and the refreshed dynCap set what is available for new sizing. Within this step the **hedge assessment** runs (BL-007, wired 18 Jul): Phase 1 — coverage matrix from the AQE `held_book` (beta-adjusted exposure, loss-per-1%-gap, gap scenarios) crossed with SRM grades and the macro posture, against the current hedge record in the journal. Phase 2 — only if coverage is short for the posture: `tools/calculators/hedge_engine.py` generates three candidate put-spread structures (chain via `alpaca_client.py`, spot via Tiger) scored by coverage-to-cost; the recommended structure enters the plan's hedge block. Skip rule retained: `position_count < 4` → skip and log. A hedge order is order-shaped like any other: it reaches the PM as a plan item and any preview routes through the staging-gatekeeper.
5. **Independent nominations — THE SWARM (explicit mechanics).** Ten SEPARATE subagent invocations, one per compiled agent file in `agents/voice-*.md` — never ten roles in one context (RB:committee.anti_anchoring). Per voice: **Claude** — spawn via the Agent/Task tool, prompt = that agent file + the universe file + the injected `tools/voice_memory.py render <voice>` block — rolling stats vs the success criteria, open picks, and STANDING LESSONS (D-14); the voice must state which lesson applies before nominating, tools disabled; **Kimi** — spawn its subagent definition from `agents/`. Each subagent is a FRESH context: no session, no other voices, no tally. All ten run in parallel; each returns `nomination.json` (contracts/nomination.schema.json); the orchestrator schema-validates each on receipt. Fewer than 10 with `shortfall_reason` is a valid outcome.
6. **Tally & tier.** Count nominations across the ten files (lens seat counts equally, D-5); stamp `price_at_nomination` into every nomination from the universe file; **also stamp `field_values` (D-20): for each nomination, look up every name in its `fields_cited` in the universe file and record the actual value — this is a deterministic dictionary lookup, no model judgement, and it is what turns each idea from a one-line assertion into a data anchor the PM can inspect.** **Also stamp `quality_flags` (D-39): run `tools/quality_flags.py derive` on each deliberation-set and held name's full AQE record and attach the fired STRENGTH/CAUTION flags (with their source values) — deterministic (law 4), the voices' own restored evaluation vocabulary, SOFT (never a tier/gate change). These travel into the deliberation packet and the plan render.** Deliberation set = RB:committee.deliberation_threshold — ≥2 nominations OR lens-top OR **a single voice at conviction ≥ RB:committee.solo_high_conviction_min (D-37: a strong lone signal is NOT relegated)**; everything else → ranked watch table (each watch row keeps its nomination_count, nominating voices, and 2–3 anchor values — never a bare ticker). ALL nominations → Nomination Ledger.
7. **Event filter (BLOCKING — runs HERE, D-11).** Apply RB:committee.event_filter to the UNION of nominated names only (~30–80 unique), after the tally, before deliberation. Flagged names are marked EVENT-DRIVEN and cannot advance — they stay visible with their flag, never silently dropped. Never run on the full universe (wasteful, wrong order — PM ruling).
8. **Macro & SRM weather.** Druckenmiller macro brief + SRM read presented as context (RB:srm.role) alongside the deliberation set — after nominations, never before.
9. **Deliberation — spawned, not inline (D-16); Risk sits at the table (D-36).** **Historical-store reconcile FIRST (D-40 — self-heal, before anything anchors on it).** The orchestrator runs `tools/historical_store.py check --list <deliberation-set + held book>`; for every name in `seed_needed` (missing, or stale past the last completed month) it pulls that name's daily history via the FMP MCP (`historical-price-eod-full`, ~6y) and runs `tools/historical_store.py seed <TICKER> --bars <file>` — a deterministic data-plane tool call, NO agent (anti-lasagna), FMP the only source (matches the DoR mandate). A name with < 12 months is recorded `deferred_too_new` and skipped on the daily pass (re-checked monthly via `--with-deferred`), never faked. So no name reaches committee/Risk un-anchored. Primary maintenance of the store is AQE's daily pipeline (Engineering & Change desk, D-40/BL-042); this step is the kernel's safety net. Then the orchestrator has **Risk** produce its anchored read per candidate + held name (ATR/structural/macro/portfolio-fit, sector-exposure impact, sizing-conviction scenarios via `book_sim`, and the post-add **parametric portfolio VaR** via `tools/calculators/var_parametric.py` — single-factor 95% 1-month, D-42, for the VaR gate) — Risk is a VOICE anchored on data, not a downstream calculator. Then it assembles the deliberation-set packet (every nominating voice's case verbatim INCLUDING its `field_values` and the stamped `quality_flags` (D-39), held-book lines, brackets, SRM weather, macro brief, live account snapshot + the Risk lens read) and spawns ONE isolated `agents/committee-desk.md` agent — judgment tier, never run inside the orchestrator's own context. It returns new-idea verdicts (ADVANCE / HOLD-FOR-CONDITIONS / PASS + conviction + mandatory bear case + dissent) AND **`held_verdicts` (D-34): a full deliberation of each HELD position — RUN / TAKE-PARTIAL / TIGHTEN / EXIT from price-vs-ATR-range, structural levels, and runner-vs-weakening momentum — plus a sector-concentration flag**, each with **`data_anchors` (D-20): the decisive field values behind the verdict** → validated against `contracts/committee.schema.json` → `data/sod/DATE/committee.json` (SOD shelf — BL-012). If a portfolio risk gate is breached and unresolved, committee-desk verdicts no ADVANCE at all — that fact leads the plan headline at step 10, same as a stand-down.
10. **Plan assembly.** For held book: the exit actions decided at step 4 (hold/trim/exit/scale-out + trailing-stop raises via `tools/calculators/trailing_stop.py`, D-33 — no longer a dangling promise). For ADVANCE names: bracket verbatim from AQE + size via `tools/calculators/sizing.py` (a wide stop is sized SMALLER, never cut — D-38) + the exact trigger. Bracket QUALITY (RR, ATR-distance, risk%) rides as a SOFT flag on the line, not a gate: "wide stop, RR 1.6 (high beta) — momentum call" — the PM sees it and decides. → **Executive Action Plan** (contracts/plan.schema.json). Every held action, new idea, and watch row carries its `data_anchors` (D-20); any name the Detect lens touched carries `lens_readings` with the lens's actual numbers. **The PHONE RENDER (D-20 anti-black-box):** fixed order (1 headline line → held actions → actionable ideas → watch table collapsed); each actionable name is one plain-language line PLUS a short "why (data):" anchor showing the 3–5 decisive numbers in plain labels — e.g. "HBAN — 4 voices, buy over 18.40, stop 17.82 (risk 2.4%), reward:risk 2.8, relative-volume 1.4x" — so the PM decides on data, never on prose alone. **Any fired quality flags (D-39) ride on the line in plain words as soft context — strength flags reinforce ("tight base + squeeze"), CAUTION flags are shown explicitly so the PM sees the warning the voices' own frameworks raised ("caution: bearish divergence", "extended +26% over SMA") — soft, never a filter; a flagged name still appears and is still actionable.** Plain words, no RB keys or raw acronyms, but the NUMBERS are always shown — that is the anchor. Exact mobile template = BL-013, format to be confirmed with the PM. Ready by 16:00.
11. **PM approval by 21:00.** **Missed-approval rule (UX-F3): one reminder at 20:30; no approval by 21:00 → the plan STANDS DOWN as DRAFT — no alerts load, nothing stages, nothing is armed. Silence never trades.** Approve/edit/reject on phone. Approved triggers → AQE intraday alert universe (all voice top-10s + held book load as alert names). For each approved actionable name the orchestrator sends a REQUEST to the staging-gatekeeper skill — the only producer of previews (RB:orders.sole_path). PM personally stages the emitted pre-authorised brackets (RB:orders.phase_1).
12. **Emit run outcome + self-heal wiring (D-45).** On completion emit the phone notification via `tools/notify.py` — `run_ok` with the plan headline (names advanced, VaR, gate state) on success, or `run_fail` (the unmistakable red page) if the phase stood down. Throughout the ladder below, **PAGE = `tools/notify.py run_fail`** (order-blind). Before standing down on a **transient** data failure (a feed/PTJ pull error — NOT a tripwire BLOCK), the orchestrator first runs `tools/self_heal.py premarket --failure <type>` (bounded retry/reseed, RB:self_heal): it heals silently and continues if it can, else escalates with the manual fix (`/recover`). A tripwire BLOCK or hard-gate breach is a **gate** — stand down, never healed. The T-minus pre-run heartbeat (RB:notifications.pre_run_minutes) is fired by the scheduler, not here.

## ON FAILURE (RB:exceptions — the ladder governs; every event writes an exception record to data/sod/DATE/exceptions/)
- Feed missing/stale, or tripwire BLOCK, or universe screen cannot run → **STAND DOWN the whole phase**: no plan, no alerts, nothing armed; PAGE. Held book stays protected by broker-side stops. Record the day as stood-down; post-market still runs.
- A voice returns nothing/invalid → re-spawn ONCE → still bad: proceed with the rest (minimum 8), tally shows the empty seats, auditor marks INCOMPLETE; morning summary.
- Hedge tools fail → plan ships WITHOUT the hedge block, flagged in the headline; morning summary.
- Deliberation cannot complete → no name gets ADVANCE (watch-table only); held actions still ship; morning summary.
- Plan fails its contract at assembly → do NOT deliver a broken plan; STAND DOWN + PAGE.
