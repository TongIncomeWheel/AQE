# PROCESS: PREMARKET (weekdays; plan ready 16:00 SGT, PM approval by 21:00 — RB:schedule)
Owner: Premarket Orchestrator. Voices work in isolation at step 6. No numbers here — all thresholds are RB: keys.

1. **Freshness check.** Journal current? AQE export dated today (RB:data_sources.staleness)? If stale → fix/notify first, do not proceed silently.
2. **Universe build.** Run `tools/universe_screen.py` (RB:universe.screen) → `data/universe/universe_YYYY-MM-DD.json`. This file is the only universe any voice sees.
3. **AQE pull.** Fetch daily export; validate against `contracts/aqe_export.schema.json`; run `tools/tripwires.py` (blocks on anomaly). Extract the working read only — full subcomponents stay on disk until a name reaches deliberation.
4. **Held book = same path, plus the hedge check.** Held positions enter the same scoring pull and the same deliberation as new candidates (no special held path). Within this step the **hedge assessment** runs (BL-007, wired 18 Jul): Phase 1 — coverage matrix from the AQE `held_book` (beta-adjusted exposure, loss-per-1%-gap, gap scenarios) crossed with SRM grades and the macro posture, against the current hedge record in the journal. Phase 2 — only if coverage is short for the posture: `tools/calculators/hedge_engine.py` generates three candidate put-spread structures (chain via `alpaca_client.py`, spot via Tiger) scored by coverage-to-cost; the recommended structure enters the plan's hedge block. Skip rule retained: `position_count < 4` → skip and log. A hedge order is order-shaped like any other: it reaches the PM as a plan item and any preview routes through the staging-gatekeeper.
5. **Independent nominations.** Spawn 9 voice agents + Detect lens as isolated subagents (RB:committee.anti_anchoring). Each receives: universe file, its data menu, its methodology card, its ledger memory. Each returns `nomination.json` (contracts/nomination.schema.json): top 10, one-line framework reason each, flags on held names.
6. **Tally & tier.**
7. **Event filter (BLOCKING — runs HERE, D-11).** Apply RB:committee.event_filter to the UNION of nominated names only (~30–80 unique), after nominations, before deliberation. Flagged names are marked EVENT-DRIVEN and cannot advance — they stay visible in the tally with their flag, never silently dropped. Never run on the full universe (wasteful, wrong order — PM ruling). Count nominations (lens seat counts equally, D-5). Deliberation set = RB:committee.deliberation_threshold. Everything else → ranked watch table. All nominations → Nomination Ledger.
8. **Macro & SRM weather.** Druckenmiller macro brief + SRM read presented as context (RB:srm.role) alongside the deliberation set — after nominations, never before.
9. **Deliberation.** Single shared session on the deliberation set only: each nominating voice states its case, mandatory bear case (RB:committee.bear_case_mandatory), unanimity challenge if triggered. Output per name: ADVANCE / HOLD-FOR-CONDITIONS / PASS + conviction + recorded dissent → `data/committee/committee_YYYY-MM-DD.json`.
10. **Plan assembly.** For held book: hold/trim/exit + stop adjustments (trailing per calculators). For ADVANCE names: bracket verbatim from AQE + size via `tools/calculators/sizing.py` + the exact trigger that makes it actionable. → **Executive Action Plan** (contracts/plan.schema.json) to Drive + phone summary by 16:00.
11. **PM approval by 21:00.** Approve/edit/reject on phone. Approved triggers → AQE intraday alert universe (all voice top-10s + held book load as alert names). For each approved actionable name the orchestrator sends a REQUEST to the staging-gatekeeper skill — the only producer of previews (RB:orders.sole_path). PM personally stages the emitted pre-authorised brackets (RB:orders.phase_1).
