# /pma — PREMARKET ANALYSIS (v5 conductor card — supersedes v4.5)

**Source of truth: `TongIncomeWheel/AQE` branch `main`.** Design record: `claude/pma_v5_design_2026-08-28.md` in the claude.ai project (PM-approved 2026-08-28). Spec annex `stages/S6B_post_committee.md` still owns the consensus rule, ranking key, ledger and card contracts — on conflict about THOSE, S6B wins; on conflict about control flow, THIS card wins.

**THE ONE-SENTENCE DESIGN.** The run is a map of steps with a scoreboard: every step reads its inputs from saved files, writes its results to saved files, and ticks the scoreboard (`run_manifest.json`, mirrored to the durable store after every tick). The conductor — the session running this card — schedules: read scoreboard → start ready steps → validate returns via `registrar.py` → commit → advance. **The conductor holds NOTHING in its own memory but the scoreboard.** Seat returns, packets, and documents pass through once, get committed, and are dropped from working context. This is the crash fix: a compaction or container reset costs at most the one step in flight, and `/pma resume` in ANY fresh session picks up from the scoreboard.

**Control vs judgment (D-16), unchanged.** The conductor forms no market opinion. Judgment lives in spawned voice agents; arithmetic lives in `pma_pipeline.py`/`pm_lens.py`/`purity_check.py`; validation lives in `registrar.py`. Every seat is spawned DIRECTLY by the conductor (run discipline 3 — a delegate cannot spawn subagents on this platform and fabricates instead of failing; a delegated stage is INVALID and re-run).

**FORMS, NOT ESSAYS (v5).** Every seat returns a single JSON object matching the house contract — Round 1: `contracts/nomination.schema.json` (bounded reasons); Round 2: `contracts/vote_round2.schema.json` (votes + bounded obligation register, ≤24KB total). `registrar.py validate` runs THE MOMENT a return lands: malformed / off-universe / wrong ticker set ⇒ REJECTED with reasons, ONE re-spawn, then the seat is marked absent and quorum math applies. The seat's thinking is its own; the reporting format is the house's. Committing a validated form via `registrar.py commit` IS the checkpoint — there is no separate checkpointing job, no heartbeat agent, no keepalive.

**PACKETS ARE INLINED, NEVER PATHS (F1, unchanged and binding).** Every spawned voice receives its packet PASTED into its prompt. The 2026-08-19 fabrication incident stands as the reason. Packets are spawn-time inputs only — consumed once, never read again downstream (PM invariant, 2026-08-28). The canonical export is the single source of truth for every later step; if a packet and the export disagree, the export wins and the stamp check has failed.

**Unattended rule, unchanged.** Never block on a question: apply the failure policy, declare every degradation in the header, publish. Footer always: "DRAFT — PM approval required. Nothing is staged, nothing is armed."

## THE MAP

```
GATHER → PREPARE → [MACRO ∥ NOMINATE] → RANK ─┬→ CHALLENGE → VOTE → DECIDE → REPEAT-WATCH ─┬→ WRITE → CHECK → PUBLISH
                                              └→ PM-LENS (independent PM lane) ────────────┘
```

A step may start only when the files it needs exist on the scoreboard (fingerprinted). A finished step is NEVER re-run — its committed files + fingerprints are proof. `/pma resume` = read scoreboard, re-run only the first step not ticked done.

### GATHER (1 spawn: `data-steward` agent — the run's ONLY contact with the outside world)
Spawn `data-steward` (agent card ships in this plugin). It fetches from `main`: `aegis/output/aqe_daily_export.json` (missing/invalid ⇒ FATAL STOP, page the PM) · `aegis/output/aqe_crown_macro.json` (missing ⇒ AQE-only, declared; byte-identical to prior session ⇒ `crown_stale`, declared) · **`aegis/output/voice_packets/` + `packet_stamp.json`** (v5 ruling #4: AQE pre-slices Round-1 packets nightly; the steward re-hashes every file against the stamp and hashes the CURRENT `voice_menus.json` against the stamp's `menus_sha256`) · tools fresh (`pma_pipeline.py`, `pm_lens.py`, `registrar.py`, `purity_check.py`), contracts (`voice_menus.json`, `vote_round2.schema.json`), `S6B_post_committee.md` · ledgers `data/pma/phase4_ledger.json` + `data/pma/verdict_ledger.json` · **FMP fundamentals batch → `fundamentals_pack.json`** (compact per-name pack for the universe or declared subset; unserved names carry `"unserved": true` — Lynch JUDGES from this pack at CHALLENGE and never fetches mid-run). Steward returns files + `data_health.json`. Conductor: `registrar.py init --date <SGT date>` first, then commit everything, tick GATHER done. Preflight is folded in here: if the GitHub connector or the durable store is unwritable, that IS the FATAL/declared outcome — test the store by writing the scoreboard mirror and reading it back.

### PREPARE (tool — a VERIFY step, not a build step)
If the packet stamp VERIFIED: accept the pre-sliced packets and `candidate_set.json` as-is. On ANY mismatch or absence: run the retained fallback — `pma_pipeline.py trim` then `packets` locally from the canonical export (the slicer is deterministic and date-seeded, so a healthy fallback reproduces the stamped bytes) — declare degradation `packet_local_slice`, continue. R3 re-check either way: one grep for `qs_market` across seat packets; a hit is FATAL at build, loud. Commit `candidate_set.json` (losing it costs every later universe check) + packets manifest. Tick.

### MACRO (2 spawns, parallel) ∥ NOMINATE (9 spawns, parallel, blind)
Unchanged judgment, v5 mechanics. MACRO: `voice-crown` (own macro file + export sector/theme layer) and `voice-druckenmiller` (macro weather + Crown DATA POINTS, never Crown's prose, never QS; MUST file agrees_on/differs_on; NEVER returns a ticker) — packets inlined. NOMINATE: one isolated spawn per nominator (elder-lens, livermore, minervini, oneil, raschke, seow, thorp, wyckoff, weis; kratter/ceponas when their books land), each getting its agent card + its own packet inlined + nothing else — no tally, no other voices, no ordering hints. Per-seat budget: 15 minutes. Each return on arrival: `registrar.py validate --round 1 --candidates candidate_set.json` → commit or reject/re-spawn-once/absent. Progress is a scoreboard read-off — print `NOMINATE: n of 9 committed` as commits land. **Barrier: both macro forms + ≥8 of 9 nominators. <8 ⇒ halt and report (no committee).**

### RANK (tool)
`pma_pipeline.py tally` then `rank --cap 20 --solo-min 4`. Qualification seat_count ≥2 OR solo conviction ≥4; fixed v4.2 key (seat_count > conviction_sum > SRM entry_gate > thematic > sc_momentum). No gate anywhere in this chain — no sector, fundamental, or bracket term (R1). **Immediately: `pma_pipeline.py ledger`** — every qualifier (survivors AND cap-cut) logged to the rolling 5-day `phase4_ledger.json`, REPEAT flags at ≥2 of trailing 5. Commit tally, phase4, updated ledger; snapshot ledger to the store this tick (mid-run wipes can no longer break the 5-day window). Tick. **The map now SPLITS into two lanes.**

### PM LANE · PM-LENS (tool, runs the moment RANK closes — never waits for votes, votes never see it)
`pm_lens.py --export <export> --phase4 phase4.json --out pm_lens.json` on the FULL export (every universe row, not just the top 20), min-checks 5 of the PM's six (C1 longlist+elder · C2 rs_leadership · C3 sector RRG, thematic RRG only if a basket exists · C4 structure_shift · C5 VWAP 5d+14d · C6 lens count ≥4 AND coil strong AND insti strong). `bracket.valid` and QS are deliberately NOT checks. Every flagged name tagged DELIBERATED / NOMINATED_CUT_BY_CAP / **UNSEEN** (passed the PM's checks, zero nominations — the TER gap). **BLOCKS NOTHING, FEEDS NOTHING UPSTREAM** (PM ruling 2026-08-19: flashed beside the committee, not inside it). Commit + tick; output joins the run again only at WRITE.

### COMMITTEE LANE · CHALLENGE (4 spawns, parallel)
Rogers + Steenbarger (challenge documents: crowding, certainty, timing / conviction audit + obligations) and Lynch + Detect-lens (Lynch judges from `fundamentals_pack.json` handed to him inlined — names unserved in the pack are declared unserved, never fetched, never invented; Detect-lens files the technical structure read). All four on the deliberation set, packets inlined. Validate/commit each on arrival, tick.

### VOTE (11 spawns: 9 nominators + lynch + detect-lens)
Round-2 packets built by `pma_pipeline.py round2packets` (deliberation set rows + attributed Round-1 reasons + all four challenge docs) and inlined per seat. Every seat files the **Round-2 vote form** (`vote_round2.schema.json`): SUPPORT/OPPOSE/ABSTAIN on EVERY deliberation-set name, conviction, bounded reasons, opposing case on every OPPOSE, self-counter on SUPPORT ≥4, falsifier, and the O-A/O-B/O-C obligation register — all bounded fields, ≤24KB. Validate on arrival (`--round 2 --phase4 phase4.json` — wrong ticker set is a rejection), commit as each lands (this is the longest, most expensive stage — per-vote commits, not end-of-stage). Progress = scoreboard read-off. **Barrier: ≥8 of 11; below ⇒ watch-table-only run, declared.**

### DECIDE (tool)
`pma_pipeline.py consensus` on the eleven committed vote files — NEVER hand-tallied, never estimated from a summary (D-16). ADVANCE = support>oppose AND support≥2 AND median support conviction ≥3; else support≥2 ⇒ HOLD-FOR-CONDITIONS; else PASS. Conviction caps per S6B. Every HOLD gets a mandatory observable condition line. Auto-bracket: levels verbatim from each name's export `bracket` block (structural if valid, else ATR fallback labelled FB) — **render-only, attaches AFTER ranking, filters nothing (R1)**. Then `pma_pipeline.py record-verdicts` — WRITE-ONCE per (date,ticker); safe on resume (re-applying an existing lock is a no-op, never a corruption); never run it off a stage that failed the direct-spawn check. Commit consensus + brackets + verdict ledger; snapshot verdict ledger to the store. Tick.

### REPEAT-WATCH (tool)
`pma_pipeline.py repeat-watch` — cross-references the rolling ledger's repeat flags against verdict-ledger history, emits `repeat_watch.json` whose `markdown` field IS §4 of the brief, verbatim, never hand-typed (PM rule 2026-08-18: "automated, not by hand"). Any past date with no ledger row prints as an explicit gap, never invented. **Then `purity_check.py --export <export>`** — (a) INVARIANCE: rank re-run with all bracket/fundamental fields stripped must produce a byte-identical ordering, else the strength chain is contaminated and the run FAILS at CHECK; SRM/thematic are NOT stripped (ratified tiebreakers in the fixed key, not gates); (b) CROWDING AUDIT: bracket-valid rate among top-supported names vs the qualifier base rate, one computed line for the brief — Rogers' 2026-08-27 hand-finding, automated. `registrar.py` has already flagged any BRACKET_BASIS reasoning per seat on the scoreboard. Commit both outputs, tick.

### WRITE (1 spawn: `brief-writer` agent)
Spawn `brief-writer` (card ships in this plugin) with ONLY the committed step outputs inlined: macro forms, phase4, consensus+brackets, repeat_watch.json, pm_lens.json, purity_check.json, fundamentals_pack.json, export held_book, data_health.json, scoreboard. Nine fixed sections, and the **connective-narrative contract (v5 §6c)**: §1 macro in plain English THEN a mandatory "what this means for the book" paragraph (held names first, then candidates); every macro claim cites its number, "no read" where none exists; §2 links sector states to the macro AND forward to where the picks/held book sit against them, uncomfortable version included; every card (shortlist, near-miss, held) carries one macro/sector context line. §4 and §6 pasted verbatim from their tools' markdown; §5 QS list rendered even when empty; crowding-audit line printed in §7's header; QS line on every card. **Narrative only — the brief-writer changes no verdict, ranking, conviction or cap.** Missing input ⇒ that section is a one-line declared gap; **the brief ALWAYS lands.** Commit the brief, tick.

### CHECK (tool)
`pma_pipeline.py gate` + the v5 additions, all mechanical: every ADVANCE has support>oppose · every HOLD has a Condition line · all sections present · zero persuasion phrasing · DRAFT footer · **Q6r** §4 is repeat_watch.json's own markdown · **Q7L** §6 is pm_lens.json's own markdown and every UNSEEN name appears · **Q0U** every ticker in the report exists in candidate_set.json (F1) · **Q3S** scoreboard shows 9+11 distinct committed seat forms from direct top-level spawns, none delegated · **Q5P (v5)** purity_check invariance = PASS, else FAIL the gate outright · **Q6c (v5)** §6c presence checks — the macro "so what" paragraph exists, macro claims carry data references, sector linkage paragraphs exist, every card has its context line; presence only, never direction of opinion. FAIL ⇒ fix at the owning stage, max 2 loops, residuals DECLARED in the footer. Never publish silently defective.

### PUBLISH
Push to `main` in ONE commit: `data/pma/<date>/` (candidate_set, tally, phase4, consensus, repeat_watch, pm_lens, purity_check, fundamentals_pack, run_manifest, vote forms) + updated `phase4_ledger.json` + `verdict_ledger.json` + `aegis/reports/pma/<date>.md` + `latest.md`. **The ONLY git write in the run.** Write the brief to the project doc `claude/pma_brief_<date>.md`. **Print the full brief on screen — the brief in chat is the deliverable, not the files.** Send the .md if the session can send files. Final scoreboard tick: run done, total tokens per step recorded — this is the PM's token meter; state the run total vs target in one line.

## THE SCOREBOARD (`run_manifest.json`)
Managed by `registrar.py` (init/commit/tick/status). Holds: run id + date, per-step status/files/fingerprints/tokens/notes, per-seat commit status + lint flags, degradations. **Mirrored to the durable store (claude.ai project doc `claude/pma_state_<date>.md` as a fenced JSON block, or the engine's equivalent) after EVERY tick.** It is the progress report, the resume point, and the token meter, all in one page. Committed seat FORMS are small (≤24KB) — commit each form's full content into the store mirror alongside the scoreboard; that is the v5 replacement for verbatim-essay checkpoints, at ~10% of the tokens, still resumable because the form IS the seat's complete return.

## FAILURE POLICY (per worker class — replaces the prose ladder)
- **Data fetch fails** → retry ×2 with backoff → declare and continue if the run can (Crown missing = AQE-only) or FATAL if it can't (no export = STOP, page the PM).
- **Packet stamp mismatch/absent** → local slice fallback at PREPARE, degradation declared, continue. Nothing halts because the pre-slice was bad.
- **Seat form malformed / off-universe / wrong ticker set** → registrar rejects ON ARRIVAL, one re-spawn, then absent (F1: whole return untrusted).
- **Seat hangs** → 15-minute budget blown = treated as malformed (one re-spawn, then absent). The rule Lynch never had.
- **Barrier under quorum** → NOMINATE <8: halt and report. VOTE <8: watch-table-only, declared.
- **Session crash / compaction / container reset** → nothing to do at crash time; `/pma resume` in a fresh session reads the store-mirrored scoreboard and re-runs ONLY the step in flight. A committed step is never re-run.
- **Durable store unwritable** → THE one hard stop. Halt, report, never proceed on local disk alone.
- **Ledger continuity** → both ledgers snapshot to the store at their ticks; write-once keyed on (date,ticker) so resume re-locks are no-ops; missing history prints as explicit gaps.
- **PM-LENS or REPEAT-WATCH tool fails** → §6/§4 render as an explicit "did not run" line; never hand-written, never silently dropped.
- **Purity invariance FAIL** → do not publish on that ranking; fix the contamination at RANK, max 2 loops, else publish watch-table-only with the failure declared in the header.
- **Brief deadline** (default: 4h after GO) → WRITE runs on whatever the store holds; missing sections are declared gaps. **The brief always lands.**
