The exact shape of every tool

Each: what goes in → what it does inside, numbered → what comes out → what happens on failure. Expanders open for detail; summaries alone give the full inventory.
Universe screen — ◐ Built · used in: Premarket step 2
Input
Market screener (US primary, ≥$2bn, actively trading) + 400 days of prices per surviving name
Internal logic
  1. Server-side cut: country, size, share type
  2. Per name: compute the 20/50/100-day exponential averages; pass if the last completed close sits at or above ANY of them
  3. Volume test: last completed day's volume ≥ its own prior-30-day average (the compared day excluded, so a spike can't inflate its own baseline)
  4. Write the passing list with the criteria embedded in the file
Output
sod/universe.json — the ONLY list any voice ever sees
On failure
A name whose data errors is skipped and counted, never guessed; no data key = cannot run at all (loud, not silent)
Feed tripwires — ✓ Verified · used in: Premarket step 3
Input
The daily quant feed + yesterday's journal + the waiver file
Internal logic
  1. Required sections all present, list non-empty
  2. Dead-signal check: any documented signal state observed ZERO times across ~180 names = alarm — unless a dated waiver names it a known engine defect (waiver expires with the fix)
  3. Sanity band: share of names with valid stop/target sets must sit in a plausible range — 100% or ~0% both alarm
  4. Dictionary drift: the feed's own glossary vs the fields actually present
  5. Held positions in the feed must match the journal's held list
  6. Staleness flag propagated if the feed isn't marked live
Output
Clean exit, or BLOCK with each failed check named
On failure
BLOCK stops the entire morning and pages you — the failure mode is loud by design
Nomination ledger — ✓ Verified · used in: Premarket 5–6 · Post-market 6–7 · Weekly 3
Input
Ten nomination files daily; a daily price table
Internal logic
  1. record: append each voice's picks; malformed files skipped AND counted; duplicates ignored
  2. track: for every open pick, fill day-1/3/5/10/15 columns in TRADING days, plus best gain and worst drawdown; close the row after 15 bars; rows with missing prices are counted, not hidden
  3. report: per voice — number of picks, hit rate at day 5, average move, exclusions disclosed
Output
The outcome memory: per-voice hit rates that feed the scorer and the weekly report
On failure
A malformed input never aborts the run; missing prices are disclosed in every report (no silent survivorship)
Sizing calculator — ✓ Verified · used in: Premarket 10 · Execution 4, 9
Input
Capital, risk multiple, entry, stop, 30-day volatility
Internal logic
  1. Step 1 — risk shares: budget ÷ (entry − stop), floored
  2. Step 2 — volatility cap: cap dollars ÷ the position's expected daily dollar movement, floored
  3. Final size = the SMALLER of the two — both steps mandatory
  4. Post-fill: actual risk = shares × (fill − stop); flag if it misses budget by more than $50
Output
Shares, dollar risk, which step capped it; post-fill verdict
On failure
REFUSES rather than computes: entry at/below stop, volatility outside a sane band (catches percent-vs-decimal mistakes), non-positive capital
Autopilot switch — ✓ Verified · used in: Approval 3 · Market hours 6 · Execution 8
Input
Your /arm · /disarm · status · count commands
Internal logic
  1. arm: writes a dated, reasoned state expiring at the NEXT 5:30am — fixed, no timezone math
  2. status: ANY read problem (corrupt file, missing field) = OFF — fail-safe by construction
  3. count: before each armed confirm, increments a counter ON DISK and refuses past the cap — survives restarts
  4. disarm: instant, one line, always wins
Output
The armed/disarmed truth the gatekeeper must read before every confirm
On failure
Fails OFF, never ON; kill conditions disarm FIRST, notify after
Parameter changer — ✓ Verified · used in: Any time you speak; Loop 3 step 2
Input
One plain-English instruction from you (e.g. 'set the size floor to 1.5bn')
Internal logic
  1. Key must already exist (new rules go the committee path, not the tweak path)
  2. Type must match — a yes/no can't replace a number (this exact bug would have made the janitor archive everything)
  3. Write the value · append a dated entry to the decisions log · commit
Output
Changed parameter + a permanent audit line
On failure
Refuses loudly with the reason; never partial-writes
Janitor — ✓ Verified · used in: Post-market 9
Input
The data shelves + the retention setting (30 days, yours to tune)
Internal logic
  1. For each dated day-folder older than retention: write a compact summary kept forever
  2. Zip the raw folder into that month's archive
  3. Remove the raw folder — the archive and summary remain
Output
Flat disk growth forever; monthly zips + permanent roll-ups
On failure
Dry-run mode proves the plan first; invalid folder names are skipped, never guessed at

On failure

Exception management — what the orchestrator does when something breaks

Ratified as ruling D-12. One ladder for every failure; refusals are designed outcomes, not errors; every event leaves a written exception record (its own contract). Two notification severities only: PAGE NOW (money or safety) and 10am summary (everything else).
1 DETECT →2 RETRY ONCE (transient pulls only — never validation failures) →3 DEGRADE (along a NAMED safe path only) →4 STAND DOWN (fail-closed when no named path exists) →5 DISARM FIRST (if armed and anything is in doubt) →6 RECORD →7 NOTIFY by severity

The three engineered loops

Loop 1 · Daily trading (closed circuit)

Each day literally feeds the next: the journal's held list is tomorrow's engine input.
1 journal → 2 quant engine → 3 tripwired feed → 4 premarket build → 5 tally + news filter → 6 deliberation → 7 plan → 8 YOUR approval → 9 gatekeeper → 10 broker → back to 1

Loop 2 · Learning (anti-decay)

Outcomes, not opinions, drive change — and every change must retire something.
1 journal → 2 outcome ledger → 3 scorer (miss classes) → 4 design & review → 5 learning agent → 6 backlog (retirement mandatory) → 7 development pipeline → 8 parameters → 9 tomorrow's premarket → back to 1

Loop 3 · Config (anti-spaghetti)

A tweak cannot happen without leaving a record, and reaches every skill only through a rebuild.
1 YOU say one line → 2 parameter changer (validate · log · commit) → 3 parameters file → 4 package builders → 5 installed package → 6 tomorrow's processes → 7 result in your plan → back to 1
