# PROCESS: MARKET HOURS (21:30–04:00 SGT; autonomous — RB:schedule)
**Desk sequence (D-26/D-32):** the Chief adopts **Execution** throughout (watch, staging), briefly re-borrowing **Research**'s voices for the intraday review pod (step 3c). Physical move to `orchestration/` = BL-033. Principle: **code watches, agents wake** (code watches (AQE alert engine); committee wakes on trigger only — no timed AI polling loops [RB:schedule.market_watch_mode]).
**Model note (D-16):** this orchestrator (and the AQE watcher it wraps) is control plane — RB:model_tiers.control. Assembling the live pack and tallying the pod's verdict is sequencing, not judgment. The pod's voices (step 3c) are the same pinned opus [RB:model_tiers.judgment] agent files as the premarket swarm — spawning them on the live pack costs nothing extra to wire, the tier travels with the agent file, not with who calls it.

1. **Alerts arrive as ONE file: the AQE alert ledger.** The AQE alert engine writes `aqe_alert_ledger.json` to the Drive "AQE" folder; the session mirrors it to `data/alerts/DATE/aqe_alert_ledger.json` and reads it with `tools/alert_ledger.py` (deterministic, no models). Contract: `contracts/alert_ledger.schema.json`. **This replaces the retired `inbox.jsonl` / `alert_inbox.py` / `alert_inbox.schema.json` trio (2026-08-06) — AQE never emitted that shape and never will. There is no JSONL, no cursor file, and no `entry_cross`/`breakout_2pct_cob`/`sl_approach`/`sl_hit` vocabulary anywhere in the live system.**
   - **Shape.** A single JSON object: `updated` · `retention_days` (30) · `events` (AQE's own event dictionary — **authoritative**) · `entries`, newest first.
   - **Cadence is NOT a clock.** AQE rewrites the whole file when its run finishes. 5 Aug produced four writes (11:07, 12:51, 14:15, 15:55 ET). Never assume 15 or 30 minutes; read `updated`.
   - **Pre-enriched at source.** Every entry already carries `scores` (sc_momentum, ptrs, elder, flow, energy, mp, mp_state), `levels` (bracket_stop, bracket_valid, tp1, last_pivot_high, atr_14d), `qs`, `structure_shift` and `intraday` context. **There is NO join back to the daily export.**
   - **Self-scoping.** `lists {on_longlist, on_elder, on_qs, held}` is stamped at source. Membership is a **flag read** — the sweep never re-derives it from `alert_list.json`.
   - **Dedupe** on `(ticker, event, time_et)`. No cursor, no state file; a re-read is idempotent and a missed cycle loses nothing.
   - **The six events, verbatim from the file:** `BOS` (closed above last confirmed pivot high) · `NEAR_BREAKOUT` (climbing into that level from below) · `NEAR_TARGET` (approaching TP1 from below) · `NEAR_STOP` (within 5% above the stop / live SL) · `MOVE` (±2% vs last close — **reference only, no entry claim**) · `VETO_HELD` (a QS veto struck a held name). If AQE ever emits an event outside this set the reader says so out loud rather than adapting silently.
   - **Routing table:**

     | Entry | Route |
     |---|---|
     | `MOVE` | **drop** — the ledger itself states no entry claim |
     | `NEAR_STOP` or `VETO_HELD`, held | **page immediately**, no committee (the risk stream) |
     | `NEAR_TARGET`, held | **manage** — trim-or-run question to the PM |
     | `BOS` or `NEAR_BREAKOUT`, on any list, `levels.bracket_valid` true | **wake the Intraday Review Pod** (step 3c) |
     | everything else (off-list, no workable bracket, not held) | **logged, visible, not podded** |

   - **Write-back.** Every entry ships with `outcome: null`. AQE never writes that field, so it is Aegis's slot: `alert_ledger.py stamp` records what each alert became (paged / podded / verdict / dropped + reason), which is what makes the day auditable and closes the learning loop.
   - **Reality check (5 Aug, 69 entries):** 61 `MOVE`, 6 `NEAR_STOP`, 2 `NEAR_TARGET`, zero `BOS`, zero `NEAR_BREAKOUT` → **2 pages, 0 pods.** That is the filter working, not the feed failing.
   - **List P (parked, D-83) still applies** where a Pipeline-Ledger row names a `{field, op, value}` trigger: the sweep checks that condition against the entry's own enriched fields. A missing field is never a satisfied trigger — logged unevaluable. A parked name that fires is podded WITH its `case_snapshot`.

   Code watches; agents wake only on a survivor.
1a. **CHEAP BY DEFAULT + HELD-BOOK FIRST (D-58, PM + Thorp).** The routine 30-min poll runs on the **watch tier = haiku** [haiku [RB:model_tiers.watch]] — never opus on a routine cycle (anti-cost, anti-overfit). Its PRIMARY, always-on job is the **held-book risk stream** (the durable positive-EV work): for every open position, on every cycle, check SL hit / SL approaching (~0.5 ATR), TP1/TP2/TP3 hit → scale-out + trail, and trailing-ratchet availability (a new higher swing-low). These are deterministic reads on the bracket + live price; haiku assembles and pages, no judgment tier needed. Held-book protection is checked BEFORE any opportunity scan.
1b. **Two wake paths for OPPORTUNITY (D-54), and when to spend a bigger model:**
   - **On-plan name** (approved actionable) crosses its live level → full re-validation (step 3) + Intraday Review Pod (step 3c).
   - **Off-plan runner** (a breakout the morning didn't pick, on the strong-momentum universe) → step 1's routing table already triaged it, so the pod runs only on the **survivors** (`BOS`/`NEAR_BREAKOUT`, on a list, valid bracket). The pod **evaluates the alert name EXACTLY as the voices evaluate a premarket candidate** (D-63, corrected) — their own methodology and normal conviction (1–5), the SAME logic as the SOD swarm. It is NOT a special "runner" mode and NOT a perfectionist stand-down; there is **one evaluation, used at SOD and intraday** (anti-spaghetti). **These voices were chosen because they are momentum traders** (O'Neil, Minervini, Livermore/Darvas lineage, Druckenmiller, Wyckoff, elder/detect), so their native lens already speaks to a momentum book — the system's ONLY duty is to not distort them: **no extension / R:R / perfection filter layered ON TOP** (that turns momentum trading into swing/position trading), and **no positive-bias cheerleading layered UNDER**. Extension above the MA is momentum STRENGTH, not a flaw (PBF, 18 Jul: mp 100, rs +66, structure 87 — 41% extended — a leader the perfectionist filter would have wrongly killed). Run the relevant voices on the live pack as a premarket-style nomination; the Chief then runs the **BRACKET EXERCISE** (stop, resistance-vs-entry, R:R — the risk, D-52) and pages the PM on genuine voice conviction with the bracket; the PM decides the R:R. **The pod runs only on survivors** (few), so a 15-min cadence stays cheap.
   - **ARMED auto-deliberate-and-execute (D-58, opt-in):** if `False [RB:autopilot.auto_deliberate_execute]` is armed, an escalated mover that reaches **consensus ≥ 6 [RB:autopilot.auto_execute_consensus_min] (6 voices)** auto-executes within caps via the staging-gatekeeper (still the sole order path); **below 6 it pages, never auto-fires.** Off-plan names still auto-execute only under this armed switch and only through the gatekeeper. Default OFF → preview/page only.
2. On an ON-PLAN trigger fire: orchestrator wakes with the alert + the approved plan entry for that name only.
3. Re-validation (short, bounded): plan conditions still true (spot vs trigger, event check, gap sanity)? Uses live spot per RB:data_sources.
3b. **Live data pack (D-13).** Assemble before any order request: live spot · distance to stop/targets from the name's feed bracket · the name's full feed record · **live sector pulse** (`tools/srm_live.py` — 11 sector ETFs + macro proxies, TAILWIND/NEUTRAL/HEADWIND + RISK_ON/OFF tone) · macro proxies. Pulse unavailable = NEUTRAL-UNKNOWN, said out loud.
3c. **Intraday Review Pod (D-13).** The alert re-convenes a BOUNDED committee: the voices that nominated this name + Druckenmiller (macro) + the Detect lens — each spawned isolated with the live pack, returning one line: **CONFIRM** or **STAND_DOWN** + reason. Majority CONFIRM required to proceed. The pod may NOT add names, may NOT change brackets or sizes, may NOT resurrect a stood-down name — confirm or stand down, nothing else. A sector HEADWIND or RISK_OFF tone is exactly the kind of reason a pod stands down. Verdict + reasons written to intraday/DATE/pod/.
4. Action by phase (RB:orders / RB:autopilot): Phase 1 — if the PM pre-staged the bracket, log the fire and monitor; if not staged, record MISSED-BY-DESIGN with price path. Any order-shaped need routes as a REQUEST to staging-gatekeeper — this orchestrator can never stage (feeds Design & Review; this is the evidence that will justify Phase 2). Phase 2 (when enabled) — auto-stage within caps, notify.
4b. **Target-hit → exits (D-33, intraday half of the trail cadence).** On a take-profit alert (price reaches TP1/TP2/TP3), the Chief adopts **Risk**'s exits skill: issue the scale-out (RB:trailing.scale_out — fraction at TP1/TP2, run the rest) AND tighten the trailing stop at once (milestone lock ≥entry after TP1, ≥TP1 after TP2). Both route as requests to the staging-gatekeeper — this orchestrator never places. Protects the spike without waiting for post-market.
5. Fills observed via broker pull → held-book memory updated (entry, stop, date, trigger, TPs) — this is Execution-class work, same field list and same journal file as the `print-trade-journal` skill's Operation 1, just triggered live instead of at post-market's end-of-day reconciliation. **Push it, same reason premarket does:** run `tools/git_sync.py -m "market-hours fill <ticker> <DATE>"` right after the update — this scheduled run is its own session with its own checkout, and a fill that only lands on this session's local disk is invisible to tomorrow's post-market carry-forward and to the next market-hours firing. Skip the push on a cycle where nothing fired (most cycles) — this is a per-fill action, not a per-poll one. Post-fill protocol runs in staging-gatekeeper (its owner), not here.
6. Every wake, one line to the overnight log — nothing else. No commentary, no re-deliberation of the plan.

## ON FAILURE (RB:exceptions; records to data/intraday/DATE/exceptions/)
- 21:25 liveness check: alert engine not alive → PAGE IMMEDIATELY (your call: fix, stay up, or accept broker stops for the night). BL-018.
- Live spot unavailable at re-validation → that trigger STANDS DOWN, logged MISSED_BY_FAILURE; never confirm on stale spot.
- Broker unreachable while ARMED → DISARM FIRST, then page. Preview mode: log and wait for the next fire.
- Gatekeeper cannot READ any check file → that is a refusal (fail-closed), not an override opportunity.
- Any anomaly at all while armed → DISARM FIRST, ask questions at 10am.
