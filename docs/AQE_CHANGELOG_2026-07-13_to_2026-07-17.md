## Thursday 2026-07-16 — data-quality guard + PTJ hardening

- `1519749` — the existing `_REQUIRED_FIELDS` schema check only verified a field's
  *key* exists, not that its *value* is non-null — a NaN engine result (thin bar
  history, an FMP gap) silently became JSON `null` and shipped undetected, and
  `held_positions` wasn't covered by the check at all. Added a value-level
  `data_quality` guard covering both, surfaced in the pipeline log, the export, and
  a Scanner UI banner — never blocks the export, only makes gaps visible.
- `76075ec` — daily Drive-folder hygiene for the PTJ journal (cleanup automation).
- **Live incident**: held positions' `entry` field came back null for every ticker
  despite a successful-looking run. `dbe3329` — root cause: a new
  `aegis_trade_journal_ARCHIVE_master.json` running-summary file (deliberately
  stripped of entry/SL/TP) landed in the same Drive folder as the real daily
  journals and had a newer `modifiedTime`, so "pick the most-recently-modified
  file" picked the archive instead of the actual journal. Fixed the selection rule
  to require the real journal's filename shape.
- `936dd17` — the PM introduced a new, permanent PTJ naming convention (dated,
  accumulating `aegis_trade_journal_YYYY-MM-DD_PTJ.json` snapshots, vs. the
  overwriting `ARCHIVE_master.json`). Updated the selection logic to match, with an
  extra safety guard: "latest" is now decided primarily by the **date encoded in
  the filename**, not Drive's mutable `modifiedTime` alone.
- `f01c600` — **fix**: the new `data_quality` guard was flagging option/hedge legs
  (covered calls, put spreads) from the PTJ as "missing" `sc_momentum`/`bracket` —
  a category mismatch, not a real gap, since options can never carry an equity
  score. Excluded non-STK held rows from the guard.
- `1fd0d5a` — paused the PTJ-cleanup GitHub Action while the PM trials a native
  Cowork-side fix for the same problem (workflow stays in the repo, easy to re-enable).

## Friday 2026-07-17 — lens consensus + a confirmed production bug fixed

- `bb69744` / `c2913bc` — **lens consensus**, a PM/AIC build order (external spec,
  independently verified line-by-line against the live 180-name export before
  merging — validated distribution matched the spec's own numbers exactly). Adds
  `lens_ranking` (new, top-level — every scored name ordered by how many of 6
  lenses agree) and `lens`/`lens_positive`/`lens_warnings` on every `daily_list`
  row. Unweighted (four prior attempts to fit weights all failed), sorts only,
  never cuts/caps/filters. One judgment call in the spec was explicitly flagged as
  not-yet-PM-ruled (whether the `structure` lens cross-checks `div_state`) — held
  for confirmation rather than shipped silently; PM ruled **Option B: `structure_shift`
  alone, no cross-check** ("you do not decide, you present") — shipped to match.
- `0b3037f` — **confirmed and fixed a real production bug**: `structure_shift`'s
  `BULLISH_BOS` state was mathematically unreachable. The comparison used
  `find_swing()`'s window-max high, and that window always includes the current
  bar — so today's close can never exceed it (proven, not just observed: verified
  0 hits in 227,717 historical rows). Independently re-derived the proof before
  fixing. Now compares against the nearest **confirmed** pivot high instead
  (already-computed, already excludes the live/unconfirmed peak) — `BEARISH_CHOCH`/
  `RANGE`/`find_swing()` itself untouched, per the AIC's 9-0 ruling scope.
- `docs/AQE_DAILY_DELIVERABLE.md`, this changelog — published.
